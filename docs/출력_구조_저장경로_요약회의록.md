# 출력 구조 · 저장 경로 · 요약/회의록 기준

이 문서는 모든 실행 경로의 산출물 기준입니다. 세부 파일명은 경로별로 조금 다를 수 있지만,
운영 기준은 아래와 같습니다.

## 경로별 지원 범위

| 경로 | 회의록/요약 | 사실검증 | Wiki Context/Proposal | Obsidian 발행 | 비고 |
|---|---:|---:|---:|---:|---|
| `run_meeting.py batch` | O | O | O | 설정 시 O | 파일 처리 표준 경로 |
| `run_meeting.py ingest` / `watch` | O | O | O | 설정 시 O | 자동 수집 경로 |
| `run_meeting.py realtime` / `record` | O | O | O | 설정 시 O | CLI 실시간 운영 경로 |
| 서버 `/ws/realtime` | O | O | O | 설정 시 O | 웹 DB에 Fact Check/Wiki 탭 저장 |
| 웹/모바일 direct OpenAI | O | X | X | X | 기기 로컬 standalone 경로 |
| `vault-audio` | O | 경로별 | 경로별 | 기존 노트 병합 | 임베드 녹음 처리 |

## 로컬 output 산출물

일반 배치 경로는 `output/{날짜_제목}/` 아래에 저장합니다.

| 파일 | 내용 |
|---|---|
| `minutes.md` | 상세 회의록. 사실검증이 켜져 있으면 `## 사실 검증` 포함. 용어·배경 검색 실패 항목은 `확인 불가`로 표시 |
| `summary.md` / `summary.txt` | 한눈에 보는 요약 |
| `script.md` / `transcript.md` | 원문 전사와 타임스탬프 |
| `script_refined.txt` 또는 `*_refined_script.txt` | STT 교정본 |
| `actions.json` / `actions.md` | 액션 아이템 |
| `wiki_context.json` | 회의록 생성에 주입된 관련 노트, evidence, registry 컨텍스트 |
| `* wiki_proposal.md/json` | 관련 Wiki 노트 업데이트 후보. 자동 반영 금지 |
| `*_fact_check.md` | 실시간/복구 경로의 별도 사실검증 파일 |
| `*_meta.json` | 실행 메타데이터와 비용 추정 |

메일 알림은 위 파일 중 존재하는 상세 회의록, 요약본, 액션, STT 원본/교정본, `segments.json`, `wiki_context.json`, `wiki_proposal.md/json`, 사실검증 파일을 함께 첨부합니다. 메일 본문만 보고 판단하지 말고 첨부의 STT 원본과 Wiki 근거 패키지를 같이 확인하는 것을 기본 운영으로 봅니다.

## Obsidian 저장 기준

`obsidian.meetings_path`가 있으면 그 경로가 우선입니다. 예:

```jsonc
"obsidian": {
  "vault_path": "D:\\Claude\\QC",
  "meetings_path": "도메인_아카이브/01_회의_세미나/회의별/{year}",
  "transcripts_path": "도메인_아카이브/01_회의_세미나/전사/{year}",
  "transcript_mode": "separate"
}
```

- 회의록 파일명: `yymmdd 제목.md`
- 별도 전사 파일명: `yymmdd 제목 - 전사.md`
- `transcript_mode = "separate"`: 전사는 별도 노트/파일로 저장
- `transcript_mode = "append"`: 전사를 회의록 본문 하단에 포함
- `transcript_mode = "off"`: 전사 저장 생략

## 요약과 회의록 분리 기준

`한눈에 보는 요약`은 30~60초 안에 판단할 수 있는 문서입니다.

- 결론
- 결정/합의
- 리스크
- 다음 액션

`회의록`은 업무 기록과 근거 보관 문서입니다.

- 안건별 상세 논의
- 수치와 근거
- 상충 의견
- 미정 사항
- 사실검증 결과

같은 내용을 요약과 회의록에 길게 반복하면 실패한 출력입니다. 요약은 회의록의 대체물이 아닙니다.

## Wiki Proposal 운영 원칙

`wiki_proposal.md/json`은 사람이 검토할 후보입니다.

- Obsidian 원본 Wiki를 자동 수정하지 않습니다.
- 충돌/불확실 주장, 새 질문, 관련 노트 업데이트 후보를 모읍니다.
- 검토 후 사람이 Wiki 노트에 반영하거나 폐기합니다.

## 모바일/standalone 주의

웹/모바일 direct OpenAI 경로는 지연이 낮고 기기 로컬 저장에 적합하지만,
서버의 Obsidian/Vault/사실검증/Wiki Proposal 파이프라인을 우회합니다.
조직 지식으로 축적할 회의는 batch, ingest, CLI realtime, 서버 `/ws/realtime` 중 하나로 처리하세요.
