## 0. 이 문서가 답하는 것

**"클라우드 SaaS(Otter·Fireflies 등) 없이, 사내 로컬 + 개인 키(BYOK)로 회의록 자동화가
성립하는가?"** — 성립한다. 우리는 그것을 제품으로 이미 돌리고 있다. 그런데 그 구성을 한 장으로
설명하는 문서가 없어서, 대외/사내 안건화나 신규 팀 온보딩 때마다 구두로 재구성해 왔다.

이 문서는 **기존 구성의 문서화**다. 여기에 적힌 것 중 새로 만들어야 하는 아키텍처는 없다.

## 1. 데이터 경계 — 무엇이 어디에 남는가

```
 ┌──────────────────────────── 내 PC (또는 사내 PC) ────────────────────────────┐
 │                                                                              │
 │  오디오 파일 ──▶ 전사(세그먼트) ──▶ 회의록/요약/액션 ──▶ 노트 폴더(.md)      │
 │      │                  │                  │                    │           │
 │  input/·업로드본    output/·SQLite      output/           Obsidian 볼트      │
 │                     (meeting_assistant.db)                 (내 폴더)          │
 │                                                                              │
 │  검색 인덱스 data/vault_index.json · 임베딩 · 지식그래프 data/wiki_graph.db   │
 │  설정·API 키  config.json (포터블은 MeetingMinutesData/ 아래)                 │
 │                                                                              │
 └────────────────────────────────┬─────────────────────────────────────────────┘
                                  │  ← 밖으로 나가는 것은 이것뿐
                    ┌─────────────┴──────────────┐
                    │  STT / LLM / 임베딩 API 호출  │   (사용자 본인 키 = BYOK)
                    │  OpenAI · Anthropic · Groq   │
                    └──────────────────────────────┘
```

| 항목 | 어디에 | 근거 |
|---|---|---|
| 오디오 원본·전사·회의록·요약 | 로컬 (`output/`, `web/meeting_assistant.db`) | `common/app_paths.py` — 포터블은 `MM_DATA_DIR` 로 앱 폴더와 분리 |
| 노트(.md)·검색 인덱스·임베딩·지식그래프 | 로컬 (`data/`, 사용자 볼트 폴더) | `wiki_core/vault_indexer.py`, `wiki_core/graph_db.py` |
| API 키 | 로컬 `config.json` 만 | 웹 화면은 마스킹, 평문 조회는 loopback 한정(`api/settings.py` `_is_local_client`) |
| **외부로 나가는 것** | STT·LLM·임베딩 **호출 페이로드** | 오디오 청크·전사 텍스트·프롬프트. 그 외 전송 없음 |

**서버 없음.** 중앙 수집 서버도, 벤더 계정 공유도 없다. 각자 PC 에서 각자 키로 돈다.

## 2. BYOK 와 폴백 체인 — 한 벤더가 죽어도 멈추지 않는다

키는 사용자가 넣는다(`api.openai_api_key` / `api.anthropic_api_key` / `api.groq_api_key`).
환경변수가 있으면 그쪽이 우선한다.

**STT 폴백 체인** (`meeting_pipeline/stt.py` `_build_stt_provider_chain`):

```
① OpenAI  models.stt          (기본 gpt-4o-mini-transcribe)
② OpenAI  models.stt_fallback (기본 gpt-4o-transcribe)   ← 모델 문제 대비(같은 벤더)
③ Groq    models.stt_groq     (기본 whisper-large-v3-turbo) ← 다른 벤더 = 진짜 백업
④ 로컬    models.stt_local    (faster-whisper)              ← 네트워크·API 전부 죽어도
```

- ④는 `stt.local_fallback=true` **이면서** 가중치가 준비돼 있을 때만 체인에 들어간다
  (준비 안 됐으면 조용히 제외 — `python run_meeting.py prepare-local-stt` 로 준비).
- ④는 **파일 업로드·폴더 감시에만** 적용된다. 실시간 녹음은 CPU 전사가 실시간을 못 따라가
  Groq 까지만 간다(설정 설명에도 명시).
- 예외뿐 아니라 **빈 전사**도 실패로 본다. 단, 정말 무음인 구간까지 전 제공자를 순회하지
  않도록 `_chunk_is_silent()` 로 한 번 갈라낸다.
- 청크마다 다른 제공자로 넘어갈 수 있으므로, **실제로 쓰인 모델은 집합**으로 회의록
  frontmatter 에 기록된다(`stt_model`·`stt_fallback_used`, §4).

**LLM**은 GPT ↔ Claude 상호 폴백(`common/llm_client.py`). `models.llm` 로 기본을 고른다.

즉 **완전 오프라인에서도 전사까지는 성립**하고(④), 회의록 생성 단계만 API 가 필요하다.

## 3. 비용 통제 — 사용자가 상한을 쥔다

구독료가 없다. 쓴 만큼만 각자 벤더에 청구된다. 그 대신 상한을 앱이 강제한다.

| 장치 | 위치 |
|---|---|
| 단가 단일 소스(STT/LLM/임베딩) | `common/pricing.py` |
| 월 지출 한도 `cost.monthly_cap_usd` | 업로드 거절(`api/batch.py`) + 임베딩 건너뜀(`vault_indexer.build_embeddings`) |
| 파일당 한도 `cost.per_file_cap_usd` | 업로드 거절 |
| 월 합계 정본(세션 + 세션 밖 사용량) | `common/usage_log.py month_to_date_spend()` |
| 화면 표시 | [대시보드] "이번 달 예상 비용" 카드 |

한도 판정은 **웹과 CLI 가 같은 함수**를 쓴다 — 기준이 갈리면 한쪽으로 우회된다.

> **추정치의 한계(정직하게)**: 표시 금액은 *설정된* 모델 단가 기준이다. 폴백으로 Groq·로컬이
> 걸린 회의는 실제보다 **크게** 나온다(전환 이력을 세션 비용에 되반영하는 경로가 아직 없다).
> 임베딩만은 API 응답의 `usage.total_tokens` 로 정확히 기록한다.

## 4. 스텔스의 반대편 — 기록으로 증명한다

로컬 실행은 "몰래 써도 된다"는 뜻이 **아니다**. 오히려 로컬·BYOK 도구일수록 개인 판단으로
쓰기 쉬워서, 참가자 동의·사내 녹취 정책과 충돌할 여지가 커진다
(근거: [`기술검토_Natively_20260730.md`](기술검토_Natively_20260730.md)).

그래서 이 제품은 두 가지를 **의도적으로** 한다.

1. **탐지 회피 기능을 만들지 않는다.** 창 숨김·프로세스 위장·화면공유 회피는 정면 불채택이다.
2. **산출물에 출처를 남긴다.** 회의록 frontmatter 에 녹취 방식·처리 시각·실제 사용 모델·
   도구 버전이 자동으로 들어간다(사용자 입력 0개). 로컬 산출물에도 같은 내용이 주석으로 붙는다.
   사용 수칙은 [`USER_GUIDE.md` §8](USER_GUIDE.md) 참고.

강제 동의 모달·전자서명은 두지 않는다 — 사내 툴 맥락에서 과하고, 매번 확인을 강요하면
읽히지 않는 클릭으로 전락한다. **강제 없는 자동 기록**이 이 트랙의 원칙이다.

## 6. 한계 (이 아키텍처가 해결하지 않는 것)

- **완전 에어갭은 아니다.** 회의록·요약 생성은 LLM API 가 필요하다. 전사만 오프라인으로 가능.
- **PC 단위다.** 여러 사람이 각자 돌리므로 회의록이 자동으로 공유되지 않는다 — 공유는 노트
  폴더(공유 드라이브·Obsidian Sync 등)나 메일 발송으로 한다.
- **비용 추정은 추정이다.** §3 의 단서 참고.
- **정책은 코드가 대신하지 못한다.** §4 의 기록은 사후 확인용이지 사전 승인 절차가 아니다.
