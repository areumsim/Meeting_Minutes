   결과가 수용 기준을 만족하는지 판정할 근거가 없었다. → 화면·상태·문구·토큰 단위로 확정했다(§5~§11).

   경계는 SEC-001 의 "로컬 전용"을 무효화하는 구성이다. → 부록 A 에서 증거와 함께 정리하고 P0 로 승격했다.
3. **계획이 "무엇을 한다"까지만 있고 "누가·언제·무엇이 끝나면 끝인지"가 없었다.** 성공 지표 중
   상당수는 현재 제품 구성으로는 측정 수단 자체가 없다. → §3.2 와 §15 에서 측정 방법·작업 분해·
   산정·완료 정의로 보완했다.
4. **기준 문서가 상정한 제품보다 실제 제품이 훨씬 크다.** 전체 탭 스냅샷에는 화면 10개, 설정 섹션

## 1. 요약

Meeting Minutes는 회의 녹음·파일 업로드, 음성 인식, 회의록 생성, 지식 관리 연동을 제공하는 로컬 우선 Windows 애플리케이션이다.

현재 프로젝트는 핵심 기능과 자동화 테스트가 상당히 갖춰져 있고 Python 테스트 720건 통과, 1건 스킵(기준일 2026-07-31 관측치) 및 프런트엔드 프로덕션 빌드 성공을 확인했다. 그러나 데이터 삭제 후 세션이 복구될 수 있는 문제, 업로드 경로 검증 부족, 로컬 API 보호 부재, 중복 실행, 비정상 종료, 평문 자격 증명, 의존성·배포 재현성 문제 때문에 현재 상태 그대로는 사내 프로덕션 릴리즈에 적합하지 않다.

v1.0.0의 목표는 기능을 더 늘리는 것이 아니라 다음 세 가지를 만족하는 것이다.

1. 사용자의 회의 데이터가 유실·부활·중복 처리되지 않는다.
2. 일반 임직원이 별도 기술 지식 없이 설치, 실행, 종료, 복구할 수 있다.
3. 미서명 배포라는 제약 아래에서 재현 가능하고 감사 가능한 사내 배포 절차를 확립한다.

## 2. 배경과 현재 상태

### 2.1 확인된 강점

- FastAPI 백엔드, React/TypeScript 프런트엔드, CLI 및 실시간 음성 인식 기능이 하나의 제품으로 구성되어 있다.
- 자동화 테스트 기반이 크고, 현재 Python 테스트 스위트가 통과한다.
- 프런트엔드 프로덕션 빌드가 성공한다.
- Windows Portable 배포를 위한 기존 빌드 스크립트와 문서가 있다.
- 설정, 회의 이력, 출력물, Obsidian 연동 등 실제 사내 사용에 필요한 기능 범위가 넓다.

### 2.3 현재 제품 표면적 (v1.2 추가)

기준 문서의 계획은 대시보드 한 화면을 상정하고 있었다. 전체 탭을 보고 나면 **문제의 성격이 달라진다.**
UI 품질 문제가 아니라, 제품이 하는 일의 범위와 PRD가 약속한 내용이 어긋나 있다.

| 축 | 실제 |
|---|---|
| 화면 | **10개** — 대시보드 · 녹음 · 업로드 · 텍스트 분석 · 위키 질문 · 회의 준비 · 회의 비서 · 지식그래프 · 도움말 · 설정 |
| 설정 | **단일 스크롤 15개 섹션** (꼭 확인 / API 키 / 모델 / 저장 위치 / 자주 쓰는 선택 / 이메일 / 노트 폴더 / 고급 8그룹 / 폴더 감시 / 처리 프로필 / 앱 종료 / 위험 구역 + JSON 직접 편집) |
| AI 벤더 | **4곳** — OpenAI · Anthropic · Groq · 로컬(faster-whisper) |
| 자동 실행 | **3종** — 폴더 자동 감시 · 회의 비서 계획 자동화 · STT 폴백 체인 |
| 외부 전송 | 회의록 전문을 외부 메일 서비스(Gmail·네이버·아웃룩 SMTP)로 자동 발송 |

이 표면적 전부에 데이터 무결성·보안·접근성·오류 처리를 채우는 일이 v1의 실제 규모다.
증거와 개별 항목은 **부록 A**, 범위 선택은 **부록 D**를 본다.

## 3. 제품 목표

### 3.1 목표

- 관리형 Windows PC에서 설치 권한 없이도 사용할 수 있는 Portable ZIP을 제공한다.
- 관리자 권한이 필요 없는 사용자 단위 설치 프로그램을 보조 수단으로 제공한다.
- 녹음, 파일 업로드, 회의록 생성, 이력 조회라는 핵심 흐름을 일반 임직원이 이해할 수 있게 한다.
- 삭제, 종료, 재실행, 업데이트 과정에서 데이터 무결성을 보장한다.
- 로컬 전용 실행을 기본값이자 v1의 유일한 지원 모드로 제한한다.
- 조직 발급 사용자별 API 키를 안전하게 저장하고 실제 값을 UI나 API로 다시 노출하지 않는다.
- 동일 소스에서 반복 생성 가능한 릴리즈와 감사 가능한 산출물을 제공한다.
- 대표 회의 데이터로 음성 인식 및 회의록 품질 회귀를 검출한다.

### 3.2 성공 지표

**개정 (2026-07-31)** — 로컬 전용·텔레메트리 없음이라는 제약 때문에, 지표 중 상당수는 **측정 수단이
정의되지 않은 상태**였다. 파일럿에서 쓸 측정 방법을 지표별로 붙인다.

| 지표 | v1.0.0 목표 | 측정 방법 |
|---|---|---|
| 데이터 유실 또는 삭제 세션 부활 | 0건 | 파일럿 주 1회 세션 수·폴더 수 대조 스크립트 + 사용자 신고 |
| 중복 처리 또는 중복 API 과금 | 0건 | 작업 기록의 동일 입력 해시 중복 호출 카운트 |
| 파일 업로드·녹음 핵심 흐름 완료율 | 95% 이상 | 로컬 작업 기록의 `completed / (completed+failed+canceled)` 를 진단 파일(익명 집계)에서 수집. 회의 제목·내용 미포함 |
| 파일 처리 실패 시 원인과 복구 방법 표시율 | 100% | 실패 건의 오류 코드 보유율. 카탈로그 미등록 코드는 자동 실패 처리 |
| 파일럿 기간 중 P0/P1 장애 | 0건 | 사내 이슈 트래커 라벨 |
| 대표 평가 세트의 결정·액션 항목 재현율 | 90% 이상 | AI-002 평가 세트 자동 실행 |
| 근거 없는 결정·액션 항목 생성 | 0건 | AI-002 평가 세트 자동 실행 |
| High/Critical 의존성 취약점 | 0건 | pip-audit · npm audit |
| 관리형 PC Portable ZIP 실행 성공 | 3대 중 3대 | 수동 검증(§14.2) |
| 첫 회의록까지 걸린 시간 | — (관찰) | 파일럿 5인 관찰 세션(1인 30분) — 문서 도움 없이 완료 여부 기록 |

**수용 기준**: 익명 집계 항목·수집 시점·저장 위치를 사전에 사용자에게 고지하고, 진단 파일 생성 시
포함 목록을 확인할 수 있어야 한다(SEC-004).

### 3.3 비목표

- Microsoft Store 또는 외부 공개 배포

- 모바일 앱의 정식 프로덕션 지원

## 4. 사용자와 핵심 시나리오

### 4.1 사용자 유형

**일반 임직원**

- API, 포트, 로컬 서버 같은 기술 개념을 알지 못한다.
- 녹음하거나 파일을 넣고 회의록 결과를 확인하는 단순한 흐름을 기대한다.
- 오류 발생 시 다시 시도할 수 있는지, 비용이 더 발생하는지 명확히 알아야 한다.

**파워 유저**

- Obsidian, 사용자 사전, 모델 선택, 자동화 기능을 활용한다.
- 상세 설정과 진단 정보가 필요하지만 일반 사용자 화면을 복잡하게 만들면 안 된다.

**내부 배포·지원 담당자**

- 버전, 체크섬, 의존성 명세, 로그, 진단 결과로 문제를 재현해야 한다.
- 사용자 API 키나 실제 회의 내용을 보지 않고도 장애를 판단할 수 있어야 한다.

### 4.2 핵심 사용자 흐름

1. 사용자가 ZIP을 풀거나 설치 프로그램을 실행한다.
2. 최초 실행에서 조직 발급 API 키를 입력하고 연결 검증을 완료한다.
3. 로컬 저장 위치와 보관 정책을 확인한다.
4. 녹음하거나 회의 파일을 선택한다.
5. 처리 전 예상 시간과 예상 비용을 확인한다.
6. 진행 상태를 보고, 필요할 경우 안전하게 취소한다.
7. 회의록을 열고 결과 파일 위치를 확인한다.
8. 이력에서 결과를 다시 열거나 휴지통으로 삭제한다.
9. 트레이 메뉴에서 앱 열기, 데이터 폴더 열기, 진단, 종료를 수행한다.

## 5. 제품 및 UX 요구사항

### UX-001 최초 실행 단순화

최초 실행은 두 단계로 제한한다.

1. 조직 발급 API 키 입력 및 실제 연결 검증
2. 데이터 저장 위치와 개인정보·보관 정책 확인

Obsidian, 이메일, 모델 세부 설정 등 선택 기능은 온보딩 완료 후 고급 설정에서 구성한다.

**수용 기준**

- 필수 API 키가 비어 있거나 연결 검증에 실패하면 다음 단계로 진행할 수 없다.
- 설정 저장에 실패하면 성공 화면을 표시하지 않는다.
- 오류에는 원인, 사용자가 할 일, 재시도 버튼을 함께 표시한다.
- 새 PC로 이동할 때 API 키는 자동 이전되지 않는다는 안내를 표시한다.

### UX-002 정보 구조 단순화

- 기본 탐색은 `홈`, `녹음`, `파일`, `이력`, `설정`을 중심으로 구성한다.
- 지식 그래프, Obsidian 및 기타 고급 기능은 별도 `지식 도구` 그룹에 배치한다.
- Obsidian 저장소가 설정되지 않은 기능은 숨기거나 비활성화 이유를 표시한다.
- 설정은 `빠른 설정`과 `고급 설정`으로 분리한다.

**수용 기준**

- 최초 사용자가 홈에서 두 번 이내의 선택으로 녹음 또는 파일 처리를 시작할 수 있다.
- 필수 설정과 선택 설정을 시각적으로 구분한다.
- 고급 설정을 열지 않아도 핵심 흐름을 완료할 수 있다.

**개정 (2026-07-31) — 정보 구조 확정**

현재 사이드바는 10개 평면 목록이고 `이력`이 없다(부록 A G-08). 좁은 화면 탭은 6개뿐이어서 회의
준비·회의 비서·지식그래프·도움말은 **도달 경로가 없다**(G-09). 항목 단위로 확정한다.

| 그룹 | 항목 | 데스크톱 | 좁은 화면 | 비고 |
|---|---|---|---|---|
| 핵심 | 홈 | 사이드바 | 탭 | 진행 중 작업 + 시작 진입점 |
| 핵심 | 녹음 | 사이드바 | 탭 | |
| 핵심 | 파일 | 사이드바 | 탭 | 기존 "업로드" 명칭 변경 |
| 핵심 | 이력 | 사이드바 | 탭 | 기존 "대시보드"가 겸하던 역할 분리 |
| 지식 도구 | 위키 질문 / 회의 준비 / 회의 비서 / 지식그래프 | 그룹 하위 | 더보기 | 저장소 미설정 시 비활성 + 사유 표시 |
| 시스템 | 설정 / 진단 / 도움말 | 사이드바 하단 | 더보기 | |

**수용 기준(추가)**

- 홈에서 클릭 2회 이내에 녹음 또는 파일 처리를 시작할 수 있다.
- 좁은 화면에서 모든 기능에 도달 가능하다(탭 5 + 더보기).
- 비활성 항목은 숨기지 않고 `왜 못 쓰는지`와 `어디서 켜는지`를 보여준다.
- 현재 위치를 `aria-current="page"`로 노출한다.

### UX-003 처리 상태와 비용 안내

- 업로드 후 예상 처리 시간과 예상 API 비용을 인라인으로 표시한다.
- 예상 비용이 미화 0.50달러 이상이거나 길이·비용 계산이 불가능할 때만 확인 모달을 표시한다.
- 처리 단계는 `준비`, `업로드`, `음성 인식`, `회의록 생성`, `저장`으로 표시한다.
- 재시도가 추가 비용을 발생시킬 수 있으면 실행 전에 알린다.

**수용 기준**

- 길이를 알 수 없는 파일은 비용 검사를 우회하여 자동 실행하지 않는다.
- 취소 가능 여부와 취소가 적용되는 시점을 표시한다.
- 오류 이후 `다시 시도`, `원본 위치 열기`, `진단 정보 복사` 중 가능한 동작을 제공한다.

**개정 (2026-07-31) — 단계·비용 표기 구체화**

현재 처리 중 세션에는 단계·진행률·남은 시간·취소가 없고 스피너와 "처리 중" 글자뿐이다(부록 A G-10).
실패한 세션에는 인라인 복구 액션이 없다(G-11).

- 파이프라인 스텝바를 도입한다. 단계 어휘는 FR-009 상태 머신을 따른다.
- 실패 세션에는 `다시 시도` · `원본 위치 열기` · `진단 정보 복사`를 인라인으로 두고, 오류 코드를
  OPS-004 카탈로그에서 가져온다.
- **2단계 보정 전사**(실시간 전사 후 확정본을 다른 모델이 다시 생성)는 비용이 사실상 2회 발생한다.
  예상 비용 계산식에 이 경로를 포함한다(G-33).
- 폴백으로 발생한 추가 비용은 원 작업 비용과 구분해 집계한다(AI-003).

### UX-004 트레이 및 종료 동작

Windows 시스템 트레이에 다음 메뉴를 제공한다.

- Meeting Minutes 열기
- 현재 작업 상태
- 데이터 폴더 열기
- 진단 실행
- 안전하게 종료

브라우저 창을 닫는 것은 앱 종료가 아님을 최초 1회 알린다.

**수용 기준**

- 처리 중 종료를 요청하면 작업 목록과 영향 범위를 보여주고 대기, 취소 후 종료, 돌아가기 중 선택하게 한다.
- 정상 종료 시 새 작업을 받지 않고 진행 중 저장을 마무리한 뒤 서버를 종료한다.
- `os._exit()` 같은 강제 종료를 정상 제품 흐름에서 사용하지 않는다.

> 참고: 현재 앱 종료 버튼은 설정 화면 맨 아래에 있고 트레이가 없다(부록 A G-34).

### UX-005 접근성과 일관된 피드백

- 브라우저 기본 `alert`, `confirm` 대신 접근 가능한 공통 다이얼로그와 토스트를 사용한다.
- 파일 드롭존, 메뉴, 모달, 진행 상태는 키보드만으로 조작 가능해야 한다.
- 모달 포커스 이동·복원, 오류 메시지 연결, 명도 대비를 검증한다.

**수용 기준**

- 핵심 흐름에 Playwright 키보드 탐색 테스트가 있다.
- 자동 접근성 검사에서 심각도가 serious 이상인 신규 위반이 없다.
- 진행 상태는 색상만으로 구분하지 않는다.

**개정 (2026-07-31)** — 적합성 목표를 명시한다. 상세 검증 항목은 **UX-011**로 분리했다.

### UX-006 (신규) 시스템 상태 상시 표시

앱 상단에 항상 한 줄로 다음을 보여준다.

| 요소 | 표시 | 실패 시 |
|---|---|---|
| 실행 경계 | `이 PC에서만 실행 중` + 바인딩 주소 | — |
| 백엔드 연결 | 정상/재연결 중/끊김 | 재시도 횟수와 `지금 다시 시도` |
| 준비 상태(readiness) | 정상 시 비표시 | 실패 항목과 조치를 배너로 승격, 새 작업 시작 차단 |
| 진행 중 작업 수 | `작업 N건` | 클릭 시 홈으로 이동 |
| 버전·빌드 | `v1.0.0 · a1b2c3d` | — |
| 데이터 폴더 | `저장 폴더 열기` | 접근 불가 시 오류 코드 표시 |
| 종료 | `안전하게 종료` | 진행 중 작업이 있으면 UX-004 대화상자 |

**수용 기준**: readiness 실패 상태에서 시작 버튼은 비활성이고, 이유와 해결 방법이 화면에 있다.
버전·빌드 문자열이 진단 출력·산출물 파일명과 일치한다(OPS-003).

### UX-007 (신규) 화면 상태 표준

데이터를 표시하는 모든 화면은 다음 5종 상태를 **모두** 구현한다. 하나라도 없으면 해당 화면은 완료로 보지 않는다.

| 상태 | 규칙 |
|---|---|
| 로딩 | 스켈레톤으로 최종 레이아웃과 같은 높이를 점유한다(레이아웃 이동 금지). 400ms 미만이면 표시하지 않는다. |
| 비어 있음 | 원인과 다음 행동을 함께 제시한다. "데이터가 없습니다" 단독 금지. |
| 필터 결과 없음 | 어떤 필터 때문인지 밝히고 되돌리는 버튼을 제공한다. |
| 오류 | 무슨 일이 있었는지 · 데이터는 안전한지 · 무엇을 하면 되는지 · 오류 코드. |
| 연결 끊김 | 앱은 계속 동작하며 진행 중 작업은 저장되어 있다는 사실을 먼저 말한다. |

### UX-008 (신규) 파괴적 작업 안전장치

- 목록에서 단일 "전체 삭제" 버튼을 제거한다. 삭제는 **선택 모드**를 거친다.
- 확인 대화상자에는 대상 건수, 대표 항목, 파일 수와 용량, 되돌릴 수 있는지, Obsidian 노트는 지워지지 않는다는 사실을 표시한다.
- 실행 후 10초간 `되돌리기` 토스트를 제공한다(휴지통 복원).
- 부분 실패 시 성공·실패를 구분해 보고하고, 실패 항목에 대해서만 다음 선택지를 준다(FR-001).
- 진행 중 세션 삭제는 중단 확인을 먼저 받는다.
- 설정 하단 위험 구역의 **"모든 기기 기록 삭제"**에도 같은 규칙을 적용하고, 별도 화면으로 분리해
  입력 확인을 받는다(부록 A G-35).

**수용 기준**: 단일 클릭으로 2건 이상을 되돌릴 수 없게 삭제하는 경로가 UI에 존재하지 않는다.

### UX-009 (신규) 용어와 문구 사전

같은 개념에 항상 같은 단어를 쓴다. 버튼 문구와 결과 문구를 일치시킨다(`휴지통으로 이동` → `휴지통으로 옮겼습니다`).

| 내부 상태 | UI 표기 | 색/아이콘 |
|---|---|---|
| `queued` | 대기 중 | 중립 · 시계 |
| `preparing` | 준비 중 | 진행 · 스피너 |
| `uploading` | 업로드 중 | 진행 |
| `transcribing` | 음성 인식 중 N% | 진행 |
| `summarizing` | 회의록 생성 중 | 진행 |
| `saving` | 저장 중 | 진행 |
| `completed` | 완료 | 성공 · 체크 |
| `failed` | 실패 | 오류 · 경고 |
| `canceled` | 취소됨 | 중립 |
| `interrupted` | 중단됨 | 주의 · 일시정지 |
| `trashed` | 휴지통에 있음 | 중립 |

금지 표현: `오류가 발생했습니다`(단독), `잠시 후 다시 시도해 주세요`(조치 없음), `Error 500`, 영문 예외 메시지 노출. 배지 `번역됨` → `영어 → 한국어`, `CLI` → `CLI로 생성`.

### UX-010 (신규) 디자인 토큰과 컴포넌트 인벤토리

색·간격·서체를 토큰으로만 사용하고 화면에서 하드코딩하지 않는다. 외부 폰트를 로드하지 않는다(오프라인 사내망 전제, 현행 유지).

- 색: 표면/선/본문 3단계 + 상태 5종(성공·진행·오류·정보·중립)을 **배경/전경 쌍**으로 정의. 상태색은 단독 사용 금지.
- 숫자(시각·길이·금액·버전)는 등폭 + `tabular-nums`.
- 최소 터치 타깃 44×44 CSS px.
- 공통 컴포넌트: 버튼(4종), 상태 칩, 배너, 카드, 세션 행, 파이프라인 스텝바, 대화상자, 토스트, 스켈레톤, 빈 상태, 필드+오류, 설정 그룹.

**수용 기준**: 신규 화면 코드에 `#RRGGBB` 직접 지정과 브라우저 기본 `alert/confirm` 호출이 없다(린트로 강제).

번호 프리셋 7종을 **언어 · 번역 · 문서 형식** 3축으로 분해하고, 조합을 저장하는 것이 기존 "처리 프로필"이 되도록 통합한다.

**수용 기준**: 새 언어나 형식이 추가돼도 선택지 개수가 곱셈으로 늘지 않는다. 선택 결과를 한 문장으로 요약해 보여준다("번역 없이 한국어 회의록을 만듭니다"). 기존 프리셋 사용자는 마이그레이션으로 동등한 프로필을 받는다.

## 6. 기능 및 데이터 무결성 요구사항

### FR-001 세션 삭제

삭제는 Windows 휴지통 이동을 기본 동작으로 한다.

처리 순서는 다음과 같다.

1. 세션이 진행 중인지 확인하고 필요하면 중단 확인
2. 출력 폴더를 Windows 휴지통으로 이동
3. 파일 이동 성공 후 DB 레코드 삭제
4. 관련 인덱스 및 UI 상태 갱신

Obsidian에 생성된 노트는 자동 삭제하지 않는다. 네트워크 공유 등 휴지통을 지원하지 않는 위치에서는 영구 삭제 또는 취소를 명시적으로 선택하게 한다.

**수용 기준**

- 삭제한 세션이 재시작 또는 폴더 재스캔 후 다시 나타나지 않는다.
- 파일 이동 실패 시 DB 레코드를 삭제하지 않는다.
- 일부 단계 실패 시 실제로 완료된 단계와 복구 방법을 표시한다.
- 전체 삭제에도 같은 규칙을 적용한다.
- 삭제 부활, 파일 이동 실패, DB 실패, 네트워크 공유 경로에 대한 회귀 테스트가 있다.

### FR-002 안전한 파일 수집

- 저장 파일명은 서버가 생성한 UUID를 사용한다.
- 원본 파일명은 표시용 메타데이터로만 보관하고 경로 구성에 사용하지 않는다.
- 확장자 허용 목록과 `ffprobe` 기반 실제 미디어 검증을 모두 통과해야 한다.
- 기본 제한은 파일 2 GiB 이하, 재생 시간 8시간 이하, 처리 시작 전 여유 공간 5 GiB 이상이다.
- 조직 정책에 따라 제한값을 설정에서 낮출 수 있다.

**수용 기준**

- `../`, 절대 경로, 예약 장치명, 중복 파일명으로 저장 경로를 벗어나거나 기존 파일을 덮어쓸 수 없다.
- 서버에서 크기 제한을 강제하고 초과 업로드를 조기에 중단한다.
- 재생 시간을 읽지 못하면 자동 처리를 시작하지 않는다.
- 형식 위장 파일, 손상 파일, 디스크 부족에 대해 사용자 친화적 오류를 제공한다.
- 실패하거나 취소된 업로드의 임시 파일을 정리한다.

### FR-003 단일 인스턴스

데이터 디렉터리별로 하나의 앱 인스턴스만 허용한다.

**수용 기준**

- 두 번째 실행은 새 서버를 띄우지 않고 기존 앱 창을 연다.
- 비정상 종료 후 남은 잠금은 프로세스 생존 여부를 확인해 안전하게 회수한다.
- 서로 다른 데이터 디렉터리를 명시한 진단·개발 실행은 별도 인스턴스로 허용할 수 있다.

### FR-004 설정 파일 무결성

- 설정 변경은 임시 파일 작성, 디스크 반영, 원자적 교체 순서로 저장한다.
- 읽기와 쓰기에 프로세스 간 파일 잠금을 적용한다.
- 마지막 정상 설정의 백업을 하나 유지한다.

**수용 기준**

- 저장 도중 프로세스를 종료해도 기존 설정 또는 새 설정 중 하나가 완전한 JSON으로 남는다.
- 손상된 설정 발견 시 백업 복구 여부를 사용자에게 알린다.
- 동시 저장 테스트와 강제 종료 테스트가 있다.

### FR-005 작업 상태 내구성

- 처리 작업의 ID, 세션 ID, 단계, 상태, 생성·갱신 시각, 오류, 재시도 가능 여부를 SQLite에 저장한다.
- 앱 시작 시 `running` 상태로 남은 작업을 검사해 안전하게 재개하거나 `interrupted`로 전환한다.
- 동일 입력과 동일 작업 ID의 중복 실행을 방지한다.

**수용 기준**

- 앱 재시작 후 마지막 작업과 실제 결과 상태가 일치한다.
- 사용자가 재시도를 명시적으로 실행하기 전 외부 API를 다시 호출하지 않는다.
- 완료한 단계의 산출물이 유효하면 불필요한 중복 과금을 하지 않는다.

### FR-006 데이터베이스 마이그레이션

- SQLite `PRAGMA user_version` 기반의 순차 마이그레이션을 도입한다.
- 마이그레이션 전 DB 백업과 무결성 검사를 수행한다.
- 실패 시 기존 DB를 보존하고 앱을 읽기 전용 복구 모드로 시작한다.

**수용 기준**

- 이전 릴리즈 데이터로부터의 업그레이드 테스트가 있다.
- 같은 마이그레이션을 두 번 실행해도 결과가 달라지지 않는다.
- 실패 메시지에 백업 위치와 복구 절차가 표시된다.

### FR-007 보관 및 정리 정책

기본 보관 정책은 다음과 같다.

| 데이터 | 기본 정책 |
|---|---|
| 성공한 업로드 임시 파일 | 결과 저장 확인 후 삭제 |
| 실패한 처리의 원본 | 7일 |
| 실시간 녹음 원본·백업 | 7일, 1일·7일·30일·영구 보관 선택 가능 |
| 앱 로그 | 14일 |
| 로그 파일 크기 | 파일당 10 MiB, 최대 10개 |
| 회의록 결과 | 사용자가 삭제할 때까지 보관 |

**수용 기준**

- 정리 예정 데이터와 기한을 설정 화면에서 확인할 수 있다.
- 정리 작업은 결과 파일과 처리 중 파일을 삭제하지 않는다.
- 정리 결과와 실패 내역을 민감 정보 없이 로그로 남긴다.

### FR-008 (신규) 사용량과 한도

- 이번 달 사용액은 **로컬 작업 기록의 추정치 합계**이며 제공사 청구액이 아님을 명시한다.
- 한도는 사용자 설정값(기본 USD 20.00), 매월 1일 로컬 시간 기준 초기화.
- 80% 도달 시 1회 알림, 100% 초과 시 새 작업 시작 전 확인을 받는다(차단이 아니라 확인).
- 취소·실패한 작업의 부분 비용도 합계에 포함한다.

**수용 기준**: 앱 재시작·마이그레이션 후에도 합계가 유지된다. 통화·기준일·"추정치" 표기가 모든 노출 지점에서 동일하다.

### FR-009 (신규) 세션·작업 상태 머신

```
queued → preparing → uploading → transcribing → summarizing → saving → completed
   │          │           │            │              │
   │          └──────────┴────────────┴──────────────┴──→ failed(재시도 가능 여부 포함)
   ├──→ canceled (사용자 취소, 단계 경계에서 적용)
   └──→ interrupted (프로세스 종료·크래시로 running 상태가 남은 경우)

interrupted → (사용자 확인) → 마지막 완료 단계 다음부터 재개
completed/failed/canceled/interrupted → trashed → (휴지통 복원) → 이전 상태
```

**수용 기준**

- 각 상태에 대응하는 UI 표기·가능 액션·비용 영향이 정의되어 있다.
- `interrupted` 재개 시 이미 완료된 단계의 외부 API를 다시 호출하지 않는다(FR-005와 연결).
- 상태 전이는 SQLite에 기록되며 UI는 서버 상태를 신뢰한다(낙관적 UI 금지).

### FR-010 (신규) 표기 규칙

| 대상 | 규칙 |
|---|---|
| 날짜·시각 | `YYYY-MM-DD HH:mm` 24시간제, PC 로컬 시간, 목록은 연도 포함 |
| 길이 | `86분 00초` / 1시간 이상은 `1시간 26분` |
| 금액 | `$0.38` 소수점 둘째 자리, 옆에 `추정` 표시, 기준일 병기 |
| 용량 | 이진 단위(GiB) 사용 시 표기도 GiB로 통일 |
| 파일명 | 표시용 원본 이름은 말줄임 처리, 저장 경로는 노출하지 않음(진단 제외) |

> 재생 시각을 다루는 코드는 공통 유틸 한 곳에서 만든다. 1시간 이상은 `H:MM:SS`로 표기한다.
> 근거는 부록 B.3(외부 시안에서 발견한 실제 결함).

### FR-011 (신규) 자동 실행 안전장치

폴더 자동 감시, 계획 자동화, 폴백 재시도처럼 **사용자가 화면을 보고 있지 않을 때 비용이 발생하는 모든 경로**에 공통 적용한다.

| 규칙 | 내용 |
|---|---|
| 기본값 | 모두 꺼짐. 켤 때 무엇을 자동으로 하는지 목록으로 보여주고 동의를 받는다 |
| 단건 상한 | 예상 비용이 상한을 넘으면 자동 실행하지 않고 **확인 대기열**에 넣는다 |
| 합계 상한 | 월 한도(FR-008)를 자동 실행에도 동일 적용하고, 자동 실행분을 따로 집계한다 |
| 일시 정지 | 모든 자동 실행을 한 번에 멈추는 스위치를 제공한다 |
| 기록 | 자동 실행으로 만들어진 세션은 `자동 실행` 표시와 트리거(감시 폴더/자동화/폴백)를 남긴다 |
| 외부 쓰기 | 노트 폴더·Obsidian에 자동으로 쓰는 동작은 대상 경로를 사전에 보여준다 |

**수용 기준**: 앱을 켜 둔 채 하룻밤이 지나도 사용자가 승인하지 않은 과금이 발생하지 않는다. 자동 실행분 비용을 별도로 조회할 수 있다.

### FR-012 (신규) 결과물 편집과 재생성

- 회의록·전사는 **읽기 전용이 아니라 편집 가능**해야 한다(현재 도움말이 편집을 안내하고 있다).
- AI 원본과 사용자 수정본을 구분해 보관한다. 재생성은 사용자 수정본을 말없이 덮어쓰지 않는다.
- 재생성 전에 수정된 위치 수와 예상 비용을 보여주고, 사본 보관 여부를 선택하게 한다.
- 화자 이름 변경은 같은 화자의 모든 발언에 일괄 적용하고, 원본 화자 라벨은 보존한다.
- 노트 폴더와 결과 폴더 **두 곳에 저장되는 경우 양쪽 반영 결과를 함께 보고**한다. 한쪽만 성공하면 부분 실패로 처리한다(FR-001과 동일 원칙).

**수용 기준**: 편집 후 재생성·앱 재시작·마이그레이션을 거쳐도 사용자 수정본이 남아 있다. 저장 실패 시 어느 쪽이 반영되지 않았는지 표시된다.

### FR-013 (신규) 녹취 고지와 산출물 출처

현재 제품이 이미 하고 있는 동작을 요구사항으로 고정한다.

- 녹음·업로드·폴더 감시 **모든 수집 경로**에 참석자 고지 안내를 표시한다.
- 탐지 회피(창 숨김, 프로세스 위장, 화면공유 회피) 기능은 제공하지 않는다.
- 산출물에는 수집 경로, 처리 시각, 사용한 STT·LLM 모델과 **벤더**, 도구 버전, 사용자 수정 여부를 기록한다.
- 이 출처 정보는 회의록 상세 화면에서도 확인할 수 있어야 한다.

**수용 기준**: 임의의 산출물 하나로 "언제·어떤 경로로·무엇을 써서 만들어졌는지"를 재구성할 수 있다.

## 7. 보안 및 개인정보 요구사항

### SEC-001 로컬 전용 네트워크 경계

- 프로덕션은 `127.0.0.1`에만 바인딩한다.
- LAN 공개 설정은 v1 UI와 프로덕션 구성에서 제거하거나 비활성화한다.
- 프로덕션 CORS 허용 목록은 비워 두고, 허용된 앱 Origin만 별도로 검증한다.
- Host 헤더는 `localhost`, `127.0.0.1` 및 실행 시 생성된 정확한 로컬 주소만 허용한다.

**수용 기준**

- 다른 PC에서 앱 포트에 연결할 수 없다.
- 허용되지 않은 Origin과 Host 요청은 상태 변경 전에 거부된다.
- DNS rebinding과 단순 폼 POST를 포함한 회귀 테스트가 있다.

### SEC-002 실행 세션 보호

- 앱 실행마다 암호학적으로 안전한 임의 세션 토큰을 생성한다.
- 프런트엔드는 제한된 부트스트랩 흐름으로 토큰을 받고 이후 REST 요청에 `X-MM-Session` 헤더를 사용한다.
- WebSocket 연결도 동일한 실행 세션과 Origin을 검증한다.
- `/api/health` 정적 리소스 및 부트스트랩에 필요한 최소 경로 외 모든 API를 보호한다.

**수용 기준**

- 토큰이 없거나 틀린 삭제, 종료, 설정 변경, 작업 시작 요청은 거부된다.
- 토큰은 로그, URL, 오류 메시지에 기록되지 않는다.
- 앱 재시작 후 이전 토큰을 재사용할 수 없다.

### SEC-003 비밀 관리

- `keyring`을 통해 Windows Credential Locker에 사용자별 API 키를 저장한다.
- 설정 JSON에는 키 존재 여부와 비밀을 식별하는 참조만 저장한다.
- 비밀 값을 다시 반환하는 `/api/config/reveal` 동작을 제거한다.
- API는 비밀 상태 조회, 저장, 삭제만 지원한다.

권장 API:

- `GET /api/secrets/status`
- `PUT /api/secrets/{name}`
- `DELETE /api/secrets/{name}`

**수용 기준**

- UI, API 응답, 로그, 진단 번들에서 API 키 원문을 확인할 수 없다.
- 연결 테스트 결과는 성공 여부와 정제된 오류만 반환한다.
- 기존 평문 키가 있으면 Credential Locker로 1회 이전하고 원문을 안전하게 제거한다.
- 사용자 간 Windows 계정이 다르면 키를 공유하지 않는다.

**개정 (2026-07-31) — 비밀의 범위**

Credential Locker 이전 대상을 다음 5종으로 확정한다. 하나라도 `config.json`에 남으면 수용 기준 미달이다.

| 비밀 | 위험 |
|---|---|
| OpenAI API 키 | 과금 도용, 회의 데이터 접근 |
| Anthropic API 키 | 동일 |
| Groq API 키 | 동일 |
| 메일 앱 비밀번호 | **메일 계정 탈취로 직결** |
| Obsidian Local REST API 키 | 노트 볼트 읽기·쓰기 |

### SEC-004 개인정보 최소화

- 회의 제목, 원본 파일명, 회의 내용, API 키는 진단 로그의 기본 수집 대상에서 제외한다.
- 오류 로그에는 내부 작업 ID와 정제된 오류 코드만 우선 기록한다.
- 사용자가 진단 번들을 만들기 전에 포함 파일 목록을 확인할 수 있어야 한다.

**수용 기준**

- 대표 회의 파일로 생성한 진단 번들에 대화 원문과 키가 포함되지 않는다.
- 예외 스택에 쿼리 문자열, 헤더, 프롬프트 원문이 노출되지 않도록 필터링한다.

### SEC-005 저장소 및 공급망

- 저장소는 사내 비공개로 운영하고 내부 전용 저작권 고지를 추가한다.
- 전체 Git 이력에 대해 비밀 탐지를 실행한다.
- Python과 npm 의존성의 SBOM을 릴리즈마다 생성한다.
- Python 임베디드 배포 파일과 FFmpeg는 승인된 출처, 정확한 버전, SHA-256을 고정한다.
- FFmpeg의 실제 라이선스 및 빌드 구성을 확인해 제3자 고지와 필요한 소스 제공 방법을 문서화한다.
- **로컬 STT 백업(faster-whisper)의 배포 용량·CPU 시간·모델 라이선스 고지를 포함한다.**

**수용 기준**

- 릴리즈 산출물에 `THIRD_PARTY_NOTICES`와 SBOM이 포함된다.
- 다운로드 파일의 해시가 다르면 빌드가 중단된다.
- 전체 이력 비밀 검사 결과가 0건이거나 승인된 오탐 목록만 남는다.

### SEC-006 (신규) 프런트엔드 신뢰 경계

- **외부 AI API 직접 호출 금지.** 프런트엔드는 loopback 백엔드에만 요청한다.
- CSP 목표값(빌드 시 nonce 주입):
  `default-src 'self'; connect-src 'self' http://127.0.0.1:* ws://127.0.0.1:*; script-src 'self' 'nonce-…'; style-src 'self' 'nonce-…'; font-src 'self'; img-src 'self' data: blob:; media-src 'self' blob: mediastream:; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`
- `unsafe-inline` / `unsafe-eval` 제거. 필요로 하는 의존성은 교체 대상으로 등록한다.
- 세션 토큰은 `localStorage`·`sessionStorage`·URL·쿠키에 저장하지 않는다. 메모리 보관 + 부트스트랩 재취득(SEC-002).
- LAN 주소 입력 UI와 설정 키를 삭제한다. 기존 설정 파일에 남아 있으면 마이그레이션에서 제거한다.

**수용 기준**: 빌드 산출물 정적 검사에서 `api.openai.com` 등 외부 도메인 문자열이 프런트엔드 번들에 존재하지 않는다. CSP 위반 리포트가 E2E 실행 중 0건.

### SEC-007 (신규) AI 벤더와 데이터 전송 승인

- 회의 음성·전사·회의록을 전송할 수 있는 벤더는 **승인 목록**으로 관리한다. 목록에 없는 벤더는 UI에서 선택할 수 없다.
- 승인 목록의 각 항목은 벤더명, 전송되는 데이터 종류, 처리 지역, 승인일, 승인자를 갖는다.
- 벤더 전환(폴백 포함)이 일어나면 **어느 벤더로 갔는지를 세션 기록과 산출물 출처에 남긴다.**
- 승인되지 않은 벤더는 기본 꺼짐이며, 켜려면 전송 사실을 명시한 동의 화면을 거친다.

**수용 기준**: 승인 목록에 없는 벤더로 나가는 요청이 코드 경로상 존재하지 않는다. 세션마다 사용된 벤더를 확인할 수 있다.

### SEC-008 (신규) 전송 계층 보안

- **TLS 인증서 검증을 끄는 사용자 설정을 제거한다**(앱 본체·Obsidian REST 양쪽).
- 사내망 SSL 검사 대응은 사내 루트 인증서 파일 경로를 등록하는 방식으로 대체한다.
- 인증서 오류는 "검증을 끄세요"가 아니라 "IT 담당자가 배포한 인증서를 등록하세요 + 진단 정보 복사"로 안내한다.

**수용 기준**: 설정 스키마·UI·코드에 검증 비활성 경로가 없다. 사내 CA 등록 후 연결 확인이 통과한다. 기존 설정에 비활성 값이 있으면 마이그레이션에서 제거하고 사용자에게 알린다.

## 8. API 및 운영 요구사항

### OPS-001 상태 확인

다음 상태 경로를 분리한다.

- `GET /api/health`: 프로세스가 응답 가능한지 확인하는 liveness
- `GET /api/readiness`: DB, 데이터 디렉터리, FFmpeg, 설정 마이그레이션 등 작업 수용 가능 여부 확인
- `GET /api/jobs`: 실행 세션에 속한 현재 작업 목록
- `GET /api/bootstrap`: 허용된 로컬 프런트엔드의 실행 세션 초기화

**수용 기준**

- FFmpeg 누락, DB 손상, 데이터 폴더 쓰기 실패는 readiness 실패로 표시된다.
- readiness 실패 상태에서 새 처리 작업을 받지 않는다.
- health 응답에는 비밀, 파일 경로, 사용자 데이터가 포함되지 않는다.

### OPS-002 진단 명령

`meeting-minutes doctor --json` 명령을 제공한다.

검사 항목:

- 제품 버전 및 빌드 식별자
- Windows 및 Python 런타임
- FFmpeg/ffprobe 존재와 버전
- DB 무결성 및 스키마 버전
- 데이터 디렉터리 읽기·쓰기 가능 여부와 여유 공간
- 단일 인스턴스 잠금 상태
- 필수 비밀의 존재 여부
- 외부 API 연결 상태(명시적 동의 시에만 실제 호출)

**수용 기준**

- 명령은 비밀과 회의 내용 없이 JSON 결과를 반환한다.
- 각 실패 항목에 안정적인 오류 코드와 사용자가 할 수 있는 조치를 포함한다.

### OPS-003 버전 일관성

Python 패키지, 프런트엔드, UI, 진단 출력, 산출물 파일명은 하나의 버전 소스에서 값을 가져온다.

**수용 기준**

- v1.0.0 빌드의 모든 노출 위치에서 동일한 버전과 빌드 커밋을 확인할 수 있다.
- 개발용 버전과 릴리즈 버전을 CI에서 검증한다.

### OPS-005 (신규) 프런트엔드 오류 처리

- 화면 단위 에러 바운더리를 둔다. 한 화면의 예외가 앱 전체를 흰 화면으로 만들지 않는다.
- 처리되지 않은 예외는 회의 내용·키를 제외하고 로컬 로그에만 기록한다(SEC-004).
- 사용자에게는 "데이터는 안전하다 + 다음 행동 + 진단 정보 복사"를 제시한다.

### 9.2 의존성 관리 기준

- Python 의존성의 기준은 `pyproject.toml`과 `uv.lock`으로 단일화한다.
- 개발, 빌드, 선택 기능 의존성을 명시적 그룹으로 분리한다.
- 배포에 포함되지 않는 `fastmcp`, `sounddevice` 등 선택 기능은 설치 누락이 제품 오류처럼 보이지 않도록 기능 플래그와 그룹으로 관리한다.
- 프런트엔드는 `npm ci`로 설치하고 lockfile 변경이 없는 빌드를 보장한다.
- 모든 보안 검사는 릴리즈 시점에 High/Critical 0건을 요구한다.
- **프런트엔드 의존성 정의·번들 예산·대량 데이터 처리 기준을 명시한다**(UX-012, 부록 A G-16).

### 9.3 v1에서 보류할 구조 변경

- 기존 SQLite 접근을 SQLAlchemy로 전면 교체하지 않는다.
- 로컬 단일 사용자 제품에 Celery, Redis, Docker를 필수 도입하지 않는다.
- 벡터 검색 기능만을 이유로 별도 벡터 데이터베이스를 도입하지 않는다.
- 대형 화면 파일의 분리는 테스트 가능성과 유지보수 개선 범위에서 단계적으로 수행한다.

## 10. AI 모델 및 품질 요구사항

### AI-001 모델 레지스트리

하드코딩된 모델 이름과 가격 정보를 중앙 `model_registry.json` 또는 동등한 단일 레지스트리로 이동한다.

각 항목은 다음 정보를 포함한다.

- 모델 ID
- 용도: 음성 인식, 요약, 보강 등
- 호환 API
- 기능 상태: 기본, 실험, 사용 중단 예정
- 단가와 통화
- 가격 확인일
- 연결 검증일
- 지원 중단 정보

**수용 기준**

- UI에는 실제 연결과 최소 품질 검증을 통과한 모델만 표시한다.
- 가격은 `YYYY-MM-DD 기준 예상치`로 표시한다.
- 확인되지 않은 신규 모델로 자동 전환하지 않는다.
- 기본 모델 변경은 아래 품질 게이트를 통과해야 한다.

> **우선순위 상향** — 모델·단가가 UI에 하드코딩되어 있고 확인일 표시가 없음이 확인되었다(부록 A G-32).

### AI-002 대표 평가 세트

개인정보를 제거하고 사용 승인을 받은 대표 회의 15건 이상으로 평가 세트를 만든다.

포함 유형:

- 한국어 일반 회의
- 영어 혼용
- 고유명사와 사내 용어
- 여러 명의 화자
- 잡음 또는 원격 회의 음질
- 긴 회의
- 결정 사항과 액션 아이템이 많은 회의

평가 항목:

- 한국어 문자 오류율 및 고유명사 정확도
- 결정 사항 재현율
- 액션 아이템 재현율과 담당자·기한 연결
- 근거 없는 결정·액션 생성 수
- 장시간 회의 누락
- 처리 시간과 예상 비용

**수용 기준**

- 후보 모델은 기존 기준 대비 주요 지표가 2%p 넘게 하락하지 않아야 한다.
- 결정·액션 항목 재현율은 90% 이상이어야 한다.
- 근거 없는 결정·액션 항목은 0건이어야 한다.
- 원본 평가 데이터는 저장소와 릴리즈 산출물에 포함하지 않는다.

## 12. 패키징 및 배포

### 12.1 Portable ZIP

Portable ZIP을 기본 배포 수단으로 한다.

- 앱과 같은 위치에 `MeetingMinutesData` 폴더를 두는 구조를 유지한다.
- 압축 해제 후 단일 실행 진입점을 제공한다.
- 실행 파일, 버전, 변경 내역, 사용자 안내, 제3자 고지, SBOM, 체크섬을 포함한다.
- SharePoint 또는 OneDrive의 접근 통제된 사내 위치에서 배포한다.

**수용 기준**

- 사내 표준 Windows PC 3대에서 관리자 권한 없이 실행된다.
- 공백과 한글이 포함된 경로에서 실행된다.
- 읽기 전용 위치에서 실행할 경우 쓰기 가능한 위치로 이동하라는 명확한 안내가 나온다.
- 기존 Portable 데이터의 백업·복원 절차를 문서화한다.

### 12.2 미서명 설치 프로그램

Inno Setup 기반 사용자 단위 설치 프로그램을 보조 배포 수단으로 제공한다.

- 설치 위치: `%LOCALAPPDATA%\Programs\MeetingMinutes`
- 데이터 위치: `%LOCALAPPDATA%\MeetingMinutes\Data`
- 관리자 권한 불필요
- 업그레이드와 제거 시 사용자 데이터 보존
- 기존 Portable 데이터 가져오기 제공

코드 서명을 하지 않으므로 Windows SmartScreen 경고 또는 회사 보안 정책에 따른 실행 차단이 발생할 수 있다. 설치 프로그램은 파일럿 PC 3대에서 실제 실행 가능함을 확인한 경우에만 배포한다. 정책상 우회가 불가능한 PC가 있으면 해당 릴리즈에서는 ZIP만 제공한다.

**수용 기준**

- 설치, 동일 버전 재설치, 상위 버전 업그레이드, 제거를 각각 검증한다.
- 제거 후 사용자 데이터가 남아 있음을 명확히 알린다.
- 설치 파일의 SHA-256을 배포 페이지에 게시한다.
- SmartScreen 대응은 사용자 우회 절차를 무조건 안내하지 않고 사내 IT 정책을 따른다.

### 12.3 수동 업데이트

- 앱 시작 시 접근 통제된 사내 버전 메타데이터를 선택적으로 확인한다.
- 새 버전이 있으면 변경 내용, 다운로드 위치, 데이터 백업 안내를 표시한다.
- 다운로드와 설치는 사용자가 명시적으로 수행한다.

**수용 기준**

- 업데이트 확인 실패가 앱 실행을 막지 않는다.
- 업그레이드 전 DB와 설정을 자동 백업한다.
- 다운그레이드는 지원하지 않으며 감지 시 데이터 변경 전에 중단한다.

### 15.5 롤백과 핫픽스

수동 업데이트 제품이므로 "되돌리기"가 자동으로 되지 않는다. 다음을 사전에 정의한다.

- **다운그레이드 금지**(§12.3). 대신 `v1.0.1` 전진 배포를 기본 대응으로 한다.
- 릴리즈 직후 결함 발견 시: 배포 위치의 파일을 내리고 공지 → 영향 사용자 식별(파일럿 명단 기준) →
  데이터 손상 가능성이 있으면 **먼저 백업 안내**를 보낸다.
- 마이그레이션이 포함된 릴리즈는 배포 전 백업 절차를 사용자 안내 1페이지로 제공한다.
- 핫픽스 목표: P0 발견부터 배포까지 영업일 2일 이내(가정, 담당자 확인 필요).

## 16. 최종 수용 기준

v1.0.0은 다음 조건을 모두 만족할 때 완료로 본다.

- 일반 임직원이 문서 도움 없이 최초 설정과 첫 회의록 생성을 완료한다.
- 삭제한 세션과 파일이 재시작 후 복구되지 않는다.
- 비정상 종료 후 상태가 일관되고 자동으로 중복 과금하지 않는다.
- 동일 데이터 폴더에 두 인스턴스가 동시에 쓰지 않는다.
- 외부 웹 페이지와 미인증 로컬 요청이 상태 변경 API를 호출할 수 없다.
- API 키 원문이 파일, UI, API 응답, 로그, 진단 번들에 남지 않는다.
- ZIP이 사내 관리형 PC 3대에서 실행된다.
- 설치 프로그램은 검증된 PC에서 실행 가능한 경우에만 보조 제공된다.
- 모든 릴리즈 게이트와 파일럿 성공 기준을 통과한다.
- 운영 담당자가 체크섬, SBOM, 제3자 고지, 진단 명령으로 배포 상태를 확인할 수 있다.

## 17. 확정 결정과 가정

### 확정 결정

- 사내 Windows 전용 v1으로 출시한다.
- Portable ZIP을 기본 배포 수단으로 한다.
- 설치 프로그램은 미서명 EXE로 제공하되 사내 정책 검증에 통과한 경우에만 배포한다.
- 코드 서명은 하지 않는다.
- 업데이트는 수동으로 수행한다.
- 삭제는 Windows 휴지통 이동을 기본으로 한다.
- API 키는 조직이 사용자별로 발급한다.
- 로컬 전용 단일 사용자 모드만 지원한다.
- 기존 대형 프레임워크를 전면 교체하지 않고 위험 구간을 우선 보강한다.

### 가정

- 사용자는 회사 관리형 Windows 계정으로 앱을 실행한다.
- 외부 AI API 사용과 회의 데이터 전송은 회사 정책 및 사용자 동의를 이미 충족하거나 릴리즈 전에 별도 승인받는다.
- 사내 SharePoint 또는 OneDrive에 접근 통제된 배포 위치를 마련할 수 있다.
- 평가용 회의 데이터는 개인정보 제거와 사용 승인을 거친다.
- SmartScreen 또는 엔드포인트 보안 정책이 미서명 EXE를 차단할 경우 ZIP 배포를 사용할 수 있다.

# 부록 B. 참고 디자인 검토 (`외부시안_gemini_20260731.html`)

시안을 화면 구성안으로 보면 **한 가지 중요한 것을 정확히 짚었다.** 현재 제품에 없는 회의록 상세 화면,
즉 전사와 결과를 나란히 놓고 고치는 화면을 제시한 점이다. 이 부분은 채택해 §11 화면 8로 발전시켰다.

다만 구현 방식은 사내 배포 제약과 여러 곳에서 충돌하므로 그대로 가져올 수 없다.

| 전사(좌) · 결과(우) 2단 구성 | 원문과 요약을 대조하며 고치는 작업에 맞는 배치. 현재 제품에 이 화면이 없다 | §11 화면 8 |
| 화자 이름 인라인 편집 | 자동 화자 분리 결과를 사람 이름으로 바꾸는 것은 실제로 가장 자주 하는 수정이다 | §11 화면 8 + FR-012(일괄 적용·원본 보존 규칙 추가) |
| 타임스탬프를 클릭 지점으로 | 요약의 각 항목에서 근거 발언으로 이동. 회의록 신뢰성 검증에 직결 | §11 화면 8(결정·액션 항목에 근거 시각 부착) |
| 녹음 종료 후 일괄 화자 분석 | 현재 설정의 `gpt-4o-transcribe-diarize — 화자분리(배치 전용)`와 일치하는 방향 | 처리 단계 정의에 반영 |
| Word·PDF 내보내기 | 회의록은 결국 공유 문서로 나간다 | §11 화면 8 내보내기 |
| 연결 상태 배지 | 방향은 맞다 | UX-006 상태 바로 흡수 |

## B.2 채택 불가

| 요소 | 문제 | 대안 |
|---|---|---|
| CDN 의존(unpkg React·Tailwind CDN·Babel standalone) | 오프라인 사내망에서 로딩 실패. 재현 가능한 빌드(§13.1)·SBOM(SEC-005) 불가. 현재 제품이 이미 "외부 폰트 의존 제거"로 정리한 방향과도 반대 | 로컬 번들 빌드 유지 |
| 브라우저에서 JSX 컴파일(Babel standalone) | `script-src 'unsafe-eval'`을 영구 요구한다. SEC-006과 정면 충돌 | 빌드 타임 컴파일 |
| **IndexedDB에 회의 원문 저장** | 진실의 원천이 두 개가 된다. 삭제·휴지통·보관 정책·백업·마이그레이션이 모두 적용되지 않는 사각지대가 생기고, 브라우저 프로필에 회의 원문이 남는다. PRD가 P0로 지목한 "삭제한 세션 부활" 문제를 다시 만드는 구조 | 저장은 백엔드 SQLite + 결과 폴더 단일 경로 유지 |
| "WebSocket 연결됨 (Server LAN)" | LAN 서버 모드는 SEC-001·§3.3 비목표에 위배 | loopback 전용 표기(UX-006) |
| `alert()`로 내보내기·저장 결과 안내 | UX-005가 금지 | 공통 다이얼로그·토스트 |
| 테마 3종(Corporate·Dark Pro·Soft Neutral) | 명도 대비·상태색 검증을 3배로 만든다. 사내 도구에서 얻는 값보다 QA 비용이 크다 | 라이트 1종 + 다크 1종, OS 설정 연동. v1.1 이후 검토 |
| 요약을 단일 `textarea`로 편집 | 결정·액션 항목의 구조가 사라져 근거 시각 연결·재생성 병합이 불가능해진다 | 구조를 가진 편집(항목 단위) |
| 화자 편집이 로컬 state에만 반영 | 저장·되돌리기·재생성 시 보존 정책이 없다 | FR-012 |

## B.3 시안에서 발견한 실제 결함 하나

타임스탬프를 `new Date(ts*1000).toISOString().substr(14,5)` 로 만들고 있다. **1시간을 넘는 회의에서
시각이 무너진다**(01:03:51이 03:51로 표시). 이 제품은 8시간 회의를 지원 범위로 잡고 있으므로 그대로
쓰면 안 된다. 시간 포맷은 공통 유틸로 한 곳에서 만들고(FR-010), 1시간 이상은 `H:MM:SS`로 표기한다.
§11 화면 8에 그 형태로 반영했다.

# 부록 C. 결정이 필요한 사항

1. **단독 모드(브라우저에서 AI API 직접 호출)와 LAN 서버 모드가 실제 코드에 살아 있는가?** 살아 있다면 v1에서 삭제하는 것으로 확정해도 되는가. (SEC-006 범위가 3 MD → 6 MD로 바뀔 수 있음)
2. 월 사용 한도(FR-008)는 **사용자 설정값**인가, 조직이 배포 시 고정하는 값인가.
3. 익명 집계 수집(§3.2)이 사내 개인정보 정책상 허용되는가. 불가하면 성공 지표를 재정의해야 한다.
4. 지식 도구 4개 화면(위키 질문·회의 준비·회의 비서·지식그래프)을 v1 범위에 포함하는가, 아니면 **그룹 이동 + 기존 UI 유지**로 두고 v1.1로 미루는가.
5. 접근성 목표를 WCAG 2.2 AA 전체로 할지, 핵심 흐름 6개로 한정할지.
6. 파일럿 5인·2주가 20건 이상 회의를 확보하기에 충분한가(주당 2건 × 5인 = 20건, 여유 없음).

**v1.2에서 추가된 결정 사항 — 앞의 6개보다 우선순위가 높다**

7. **API 키를 조직이 발급하는가, 사용자가 개인 계정으로 발급하는가.** 현재 도움말은 개인 발급·개인 결제를 안내하고 PRD는 조직 발급을 전제한다. 둘 중 하나로 확정해야 비용 정산·DPA·퇴사자 키 회수·도움말 문구가 모두 정해진다. **이 결정 없이는 릴리즈할 수 없다.**
8. **승인된 AI 벤더는 어디까지인가.** OpenAI만인가, Anthropic·Groq도 포함인가. Groq 폴백을 유지한다면 회의 음성의 국외 이전 검토가 끝나 있어야 한다.
9. **부록 D의 안 A(코어 릴리즈)와 안 B(전체 릴리즈) 중 무엇으로 가는가.** 일정과 인원이 여기서 갈린다.
10. **이메일 자동 발송을 v1에 유지하는가.** 유지한다면 회의록 전문이 외부 메일 서비스로 나가는 것에 대한 사내 승인이 필요하고, "데이터는 이 PC에 남습니다" 안내 문구를 정정해야 한다.
11. **폴더 자동 감시를 v1에 유지하는가.** 유지한다면 FR-011 안전장치가 선행되어야 한다.
12. 로컬 STT 백업(faster-whisper) 모델 파일을 배포에 포함하는가. 포함 시 배포 용량과 제3자 고지 범위가 바뀐다.

# 부록 D. v1 범위 선택

전체 탭을 보고 나서의 판단은 분명하다. **현재 표면적 그대로 v1.0.0을 프로덕션 품질로 끌어올리는 것은
권고하지 않는다.** 화면 10개 × 상태 5종, 설정 15섹션, 벤더 4곳, 자동 실행 3종 전부에 데이터 무결성·
보안·접근성·오류 처리를 채우는 일이기 때문이다. 앞선 v1.1 산정(115 MD)은 대시보드 기준이었고, 전체
표면적을 반영하면 **175~200 MD 규모**로 늘어난다.

두 가지 선택지를 제시한다.

| | 안 A · 코어 릴리즈 (권고) | 안 B · 전체 릴리즈 |
|---|---|---|
| v1.0.0 범위 | 홈·녹음·파일·이력·회의록 상세·설정·도움말 + 텍스트 분석 | 현재 10개 화면 전부 |
| v1.1로 이관 | 위키 질문, 회의 준비, 회의 비서(자동화 포함), 지식그래프, 이메일 자동 발송, 폴더 자동 감시 | 없음 |
| 개발 규모 | 약 **145 MD**(§15.2 합계 기준) | 약 **190 MD** |
| 일정(3인) | 약 11주 + 파일럿 2주 | 약 14주 + 파일럿 2주 |
| 위험 | 이관 기능은 "설정에서 숨김" 처리 필요, 기존 사용자 반발 가능 | 자동 실행·다중 벤더까지 한 번에 검증해야 해 파일럿 실패 확률이 높다 |
| 근거 | 이관 대상은 모두 **Obsidian 노트 폴더 연결이 전제**인 파워 유저 기능이다. §4.1의 주 사용자(일반 임직원)는 쓰지 않는다 | — |

안 A를 택하면 이관 기능은 삭제가 아니라 **기능 플래그로 비활성**하고, 파워 유저에게는 현행 빌드를
유지하는 방식이 안전하다.

이 결정(부록 C #9)이 나기 전까지 §15.2 이하의 산정은 **안 A 기준**이다.
