# 배포(릴리즈) 절차 — 포터블 zip + GitHub Releases

사내 배포본을 만들어 전달하는 순서. **정본 배포 방식은 포터블 zip** 이다
(임베디드 파이썬 + `MeetingMinutes.bat`). 구형 PyInstaller exe 는 원격 MCP(`/mcp`)가
필요할 때만 쓰는 대체 경로이며, 필요하면 **별도 릴리즈 자산**으로 올린다.

> `dist/` 는 `.gitignore` 대상이다 — 배포본을 git 히스토리에 커밋하지 않는다.
> zip 이 ~100MB 라서 커밋하면 릴리즈마다 리포가 100MB씩 영구히 늘고, GitHub
> 파일 한도(104.8MB)를 넘는 순간 push 자체가 거부된다. **배포는 Releases 로.**

## 0. 빌드 전 체크리스트

- [ ] 배포에 넣을 변경이 **모두 커밋**돼 있는가 (`git status` 깨끗)
      — 빌드는 워킹트리를 그대로 담는다. 미커밋 작업이 섞이면 그대로 배포된다.
        (과거 사고: ① 커밋 HEAD로 빌드해 미커밋 기능이 빠짐 ② 반대로 다른 세션의
        미완성 작업이 섞임 → 둘 다 "깨끗한 커밋 상태에서 빌드"로 예방)
- [ ] `python -m pytest` 통과
- [ ] `config.example.json` 의 기본값이 배포에 맞는가 (특히 `realtime.language`)
- [ ] 실기동 스모크: 녹음 30초 → 회의록 생성 → 대시보드 표시

## 1. 포터블 빌드

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build\build_portable.ps1
```

산출물:
- `dist\MeetingMinutesPortable\` (풀어놓은 폴더 — 로컬 확인용)
- `dist\MeetingMinutesPortable.zip` (**배포용, 사용자 데이터 제외**)

빌드 스크립트가 프런트엔드(`npm install` + `npm run build`)까지 수행하고,
임베디드 파이썬을 `vendor\python-embed\` 에 캐시한다(첫 회는 다운로드 필요).

## 2. 배포본 검증 (필수)

```powershell
# 1) 시크릿 유출 확인 — 개인 config.json 이 zip 에 들어가지 않았는지
Get-ChildItem dist\MeetingMinutesPortable -Recurse -Filter config.json
#    → 결과가 없어야 정상 (config.example.json 만 있어야 함)

# 2) 압축 해제본으로 실행 확인
dist\MeetingMinutesPortable\MeetingMinutes.bat
#    → 브라우저 열림 / /api/health ok / 녹음 시작 가능
```

## 3. GitHub Release 작성

1. https://github.com/areumsim/Meeting_Minutes/releases → **Draft a new release**
2. 태그: `v2026.MM.DD` (예 `v2026.07.29`) / 대상 브랜치: `main`
3. 제목: `회의록 자동화 v2026.MM.DD (포터블)`
4. 본문: `docs/RELEASE_NOTES_최신.md` 내용을 붙여넣고 이번 변경으로 갱신
5. 자산 첨부: `dist\MeetingMinutesPortable.zip`
6. exe 도 배포한다면 **별도 릴리즈**(태그 `v2026.MM.DD-exe`)로 올려
   "원격 MCP 필요할 때만 쓰는 대체 배포본"임을 본문에 명시한다.
   실측(2026-07-29 빌드, 같은 PC): **첫 실행 포터블 약 12초 vs exe 약 85초**
   (미서명 PyInstaller 부트로더 백신 스캔). exe 릴리즈 본문에 "첫 실행이 1~2분
   걸릴 수 있습니다 — 창이 안 떠도 기다리세요"를 꼭 넣는다.

### 산출물 크기 참고 (2026-07-29 빌드)

| 파일 | 크기 | 비고 |
|---|---|---|
| `MeetingMinutesPortable.zip` | **185.5 MB** (2026-07-29 로컬 STT 백업 번들 이후) | 정본. **git 100 MiB 한도 초과** — Releases 자산으로만 배포 |
| `MeetingMinutesPortable.zip` | 95.3 MiB (그 이전) | faster-whisper 번들 전 크기 |
| `MeetingMinutes.zip` (exe) | 104.7 MiB | **git 100 MiB 한도 초과** — Releases 자산으로만 배포(자산 한도 2 GiB) |

> 포터블이 커진 이유: 오프라인 최종 백업(`faster-whisper` + ctranslate2·av·onnxruntime·numpy)
> 라이브러리를 넣었다(+약 90MB). 모델 가중치는 넣지 않았고 사용자가 [설정]에서 내려받는다
> (`tiny` 74.6MB / `base` 약 145MB, 저장 위치 `MeetingMinutesData\data\models`).
> 용량이 문제라면 `scripts/build/requirements-web.txt` 의 `faster-whisper` 한 줄을 빼면
> 95MB 수준으로 돌아간다(그 배포본에서는 로컬 백업이 동작하지 않고 Groq까지만 폴백).

> 원격이 **공개 리포**다. 릴리즈 자산도 누구나 내려받을 수 있으니, 사내 한정
> 배포가 필요하면 Releases 대신 사내 OneDrive/SharePoint 링크를 쓴다.

### gh CLI 로 자동화하려면

```powershell
winget install GitHub.cli
gh auth login
gh release create v2026.MM.DD dist\MeetingMinutesPortable.zip `
   --title "회의록 자동화 v2026.MM.DD (포터블)" `
   --notes-file docs\RELEASE_NOTES_최신.md
```

## 4. 배포 후

- 사용자 안내는 `docs/USER_GUIDE.md` 링크로 대체 (릴리즈 본문에도 3단계 요약 포함)
- 기존 사용자는 zip 을 새로 풀고 **`MeetingMinutesData\` 폴더만 그대로 복사**하면
  설정·데이터가 유지된다 (릴리즈 본문에 이 문장을 꼭 넣는다)
