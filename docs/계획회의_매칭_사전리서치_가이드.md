## 1. 무엇이 추가됐나

1. **계획 회의 매칭** — 녹음이 끝나 회의록을 만들 때, 같은 날짜에 미리 만들어 둔
   `status: planned` 노트를 찾아 연결합니다. (날짜 일치 + 제목 유사도)
2. **병합 전 사용자 확인** — 매칭돼도 자동으로 합치지 않고, 합치기 전에 사용자에게
   `[Y=병합 / n=새 노트]` 를 물어봅니다. 비대화형(웹/워처)에서는 절대 자동 병합하지 않습니다.
3. **병합** — 확인하면 계획 노트의 사전 내용(사전 조사·안건·메모)은 그대로 두고,
   아래에 `## 회의 기록` 으로 요약/본문/용어·배경/액션/참고를 덧붙이고
   `status: planned → done`, 참석자는 계획값∪감지값으로 합칩니다.
4. **사전 리서치 자동 실행** — 계획 노트에 안건/주제를 적어 저장하면 워처가 감지해
   핵심 용어·인물·기관을 뽑고 LLM 웹검색 설명 + 볼트 내 관련 노트 링크를
   `## 사전 조사` 에 채웁니다. (안건이 그대로면 재실행 안 함 — `research_hash`)
5. **회의 후 품질 루프** — batch, ingest, CLI realtime, 서버 `/ws/realtime`은 회의록 생성 후
   노트 대조, `wiki_context.json`, `wiki_proposal.md/json`, action/decision registry 갱신을 수행합니다.

## 2. 매칭 규칙 (오매칭 방지)

- **날짜**: 녹음 날짜(`session_dt`, 파일명/세션시각에서 추출)와 노트 `date` 가 같은 날일 때만.
  둘 다 날짜가 있는데 다르면 매칭하지 않음.
- **제목**: 공백·기호 무시 정규화 후 점수화 — 완전일치(3) / 포함(2) / 단어겹침(1) / 불일치(0).
  예) 녹음 "주간 보고" ↔ 계획 "주간보고" = 3, "코워크 교육" ↔ "코워크 사용법 교육" = 1.
- **시간 근접(제목이 안 겹쳐도 후보)**: 제목 점수가 0이어도, 계획 노트의 `time`과 녹음 시각이
  `obsidian.match_time_window_min`(기본 **±120분**) 이내면 후보가 됩니다(양쪽에 시각 정보가 있을 때) —
  같은 시간대 회의 매칭용. 즉 후보 조건은 **같은 날짜 + (제목 유사 OR 비슷한 시간대)**.
  우선순위는 제목점수 > 시간근접 > 시간차 작은 순.
- **status: planned** 노트만 후보. `done` 등은 건너뜀.

## 3. 화면별 모습 (꼼꼼 검토)

### (A) 터미널 / CLI — 확인과 결과가 여기서 보임
배치 처리(`run_meeting.py batch ...` 또는 `scripts/windows/run_batch.bat`) 중 매칭되면:

```
  ── 계획된 회의와 일치하는 노트를 찾았습니다 ──
     노트   : 00_Meetings/팀회의/2026-06-27 주간보고.md
     제목   : 주간보고  (녹음 제목: 주간 보고)
     날짜   : 2026-06-27 09:00
     참석자 : 최민석, 정하윤, 최문수, 심아름
  이 계획 노트에 회의록을 병합할까요? [Y=병합 / n=새 노트] : y
  ✅ 계획 회의에 병합 → 00_Meetings/팀회의/2026-06-27 주간보고.md  (status: planned → done)
```

n 을 고르면: `계획 회의 매칭됨(병합 보류): … → 새 노트로 생성` 후 평소처럼 새 노트 생성.
`config.json → obsidian.auto_merge: true` 면 묻지 않고 항상 병합.

### (B) Obsidian 노트 — 실제 결과물 (사용자의 주 화면)

**사전 리서치 후 (녹음 전):**
```
## 사전 조사
> (보고 전 준비 메모)

<!-- 🔎 auto-research:begin -->
> 🔎 회의 전 자동 리서치 · LLM 웹검색 기반 · 2026-06-26 09:00
**핵심 용어·인물·기관**
- **코워크** (용어·기술): …
- **온톨로지** (용어·기술): …
**볼트 내 관련 노트**
- [[코워크 메모]]
**외부 참고자료**
- [코워크 문서](https://…)
<!-- 🔎 auto-research:end -->

## 안건
- 코워크 기본 사용법
```

**병합 후 (녹음 후):** 위 사전 내용은 그대로 유지되고 맨 아래에 추가 —
```
status: done   (프론트매터)
---
## 회의 기록 (2026-06-26 15:40)
### 한눈에 보는 요약
- …
### 용어·배경 / ### 액션 아이템 / ### 참고 자료
```

### (C) 웹 UI — 검토 결과
매칭·병합·사전리서치는 **Obsidian 볼트에서 일어나는 동작**이고, 이 도구의 웹 대시보드는
`output/` 의 *오디오 처리 세션* 을 보여주는 별개 화면입니다. 따라서:

- 서버 `/ws/realtime`은 입력 프롬프트가 없는 **비대화형**이라 원칙(합병 전 확인)에 따라
  **자동 병합하지 않고** 새 노트를 만들되, 매칭 정보는 Obsidian 메타데이터와 대시보드에서 확인할 수 있게 둡니다.
- 프론트 standalone/mobile direct OpenAI 경로는 서버 파이프라인을 우회하므로 계획 매칭/병합과 Wiki 품질 루프를 수행하지 않습니다.
- 웹에서 "계획 매칭됨/병합 대기" 배지를 보여주려면 별도 작업이 필요합니다(권장, 아래).

권장 최소 패치(후속 작업으로 가능):
- 백엔드: `sessions` 테이블에 `planned_match TEXT` 컬럼 추가 → `enrich_and_publish` 반환의
  `planned_match` 를 세션에 저장.
- 프론트: `Dashboard.tsx` 의 배지 영역(타입/CLI 배지 옆, 약 150행)과
  `SessionDetail.tsx` 헤더에 `계획 매칭` 배지 + "병합 확인" 버튼(2단계 확인 다이얼로그) 추가.
- 이렇게 하면 웹에서도 "이 녹음은 6/27 주간보고 계획과 일치 — 병합할까요?" 를 띄울 수 있습니다.

## 4. 사용법

### 사전 리서치 워처 켜기
```
scripts/windows/run_plan_watcher.bat              ← config.json의 obsidian.vault_path 를 감시
또는  python run_meeting.py plan-watcher --vault "D:\Claude\QC"
       python run_meeting.py plan-watcher --once   (한 번만 전체 스캔, 테스트용)
```
켜 두면 계획 노트에 안건을 적고 저장할 때마다 `## 사전 조사` 가 자동으로 채워집니다.
(선택) `config.json → obsidian.vault_path` 를 넣으면 `--vault` 생략 가능.
기준 볼트는 `D:\Obsidian\MyVault`입니다.

### 매칭/병합
별도 설정 없이 동작합니다. 녹음→회의록 생성(배치) 시 같은 날짜·제목의 planned 노트가 있으면
터미널에서 병합 여부를 물어봅니다. 항상 병합하려면 `config.json` 에 `"obsidian": { "auto_merge": true }`.

## 5. 일정 관리 · 충돌 점검 · 대시보드 (`plan_schedule.py`)

볼트의 회의 노트(프론트매터 date/time/attendees/status)를 읽어 **일정 정리 + 충돌 감지 +
Obsidian 대시보드**를 만듭니다. 실행은 **Cowork에서 요청 시**가 기본(원하면 CLI/`scripts/windows/run_plan_schedule.bat`).

- **충돌/중복**: 두 회의의 시간 구간이 겹치면 `시간겹침`, 같은 참석자가 겹치면 `이중예약`으로 표시.
- **준비 미비**: 임박(기본 3일)한 planned 회의인데 안건·사전조사가 비어 있으면 경고.
- **대시보드**: `00_Meetings/_일정.md` 에 다가오는 회의 표 + 충돌/준비미비 + 전체 Dataview 자동 생성.

```
scripts/windows/run_plan_schedule.bat
또는  python run_meeting.py schedule --vault "D:\Claude\QC" --write-dashboard [--days 14]
```

Cowork 사용 예: "이번 주 회의 정리해줘", "겹치는 일정 있어?", "다음 회의 준비됐어?" 라고 물으면
이 도구를 돌려 정리·점검 결과로 답합니다.

### 웹 확인(우선순위 4) → Cowork + 대시보드 방식 채택
웹/모바일 direct 경로는 오프라인(IndexedDB) 중심 구조라 Obsidian 볼트를 직접 운영하지 않습니다.
대신 서버/CLI 경로에서 비대화형 녹음이 계획과 매칭되면 그 녹음 노트에 `matched_plan` 을 기록하고
일정 대시보드의 **"병합 대기"** 에 표시합니다. Cowork(여기)에서 "맞는지 확인 후 병합해줘" 라고 하면
`ObsidianClient.merge_recording_into_plan()` 으로 계획 노트에 병합(status→done, 참석자 합집합)합니다.

## 6. 설계상 의도적으로 둔 부분

- **제목 약매칭(점수 1, 토큰 겹침)·시간 근접(제목 점수 0)**: 느슨해 보이지만 **병합 전 사용자 확인**이 안전장치라 허용. 단 같은 날짜가 전제(양쪽 날짜가 다르면 제외)이며, 제목이 안 겹쳐도 비슷한 시간대(±120분)면 후보가 됨.
- **계획 노트 탐색은 00_Meetings 1단계 하위까지**: 현재 볼트 구조(프로젝트별 1단계)에 맞춤. 더 깊은 트리는 향후 필요 시 확장.
- **비대화형(웹/워처)에서는 자동 병합 안 함**: "합병 전 확인" 원칙. 웹 확인 UI가 이 자리를 채울 예정.
