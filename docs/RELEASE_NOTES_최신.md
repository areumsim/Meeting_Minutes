## 시작하기 (3단계)

1. `MeetingMinutesPortable.zip` 다운로드 → **압축 해제**(폴더째 원하는 위치로)
2. 폴더 안의 **`MeetingMinutes.bat`** 더블클릭 → 브라우저가 열립니다(10초 정도)
3. 처음 열리는 설정 마법사에서 **OpenAI API 키**만 넣으면 준비 완료

- 파이썬·ffmpeg 설치 불필요(모두 포함). 관리자 권한도 필요 없습니다.
- 자세한 사용법은 [사용자 가이드](../docs/USER_GUIDE.md) 또는 앱 안의 **[도움말]** 화면.
- 문제가 생기면 같은 폴더의 **`Troubleshoot.bat`** 을 실행해 로그를 확인하세요.
- 지금 쓰는 빌드가 무엇인지는 폴더의 **`BUILD_INFO.txt`**(커밋·빌드시각)에서 확인합니다.

### 이미 쓰고 있던 분 (업데이트)

1. 실행 중인 앱을 **모두 종료**합니다(작업 관리자에서 `pythonw.exe` 가 남아 있으면 종료).
   여러 번 실행해 인스턴스가 겹쳐 있으면 옛 버전 창을 붙잡고 테스트하게 됩니다.
2. zip 을 **새 폴더**에 풀고, 기존 폴더의 **`MeetingMinutesData\` 폴더만 복사**해 옵니다
   → 설정(API 키)·회의록·DB가 그대로 유지됩니다.
3. ⚠️ **[설정] → 실시간 녹취 → 기본 언어가 `ko`(한국어)인지 확인**하세요.
   기존 `config.json` 은 사용자 파일이라 새 버전이 값을 덮어쓰지 않습니다 —
   예전 기본값 `en` 이 남아 있으면 한국어 회의를 영어로 인식해 엉뚱한 전사가 됩니다.
   (녹음 시작 화면의 모드도 **"한국어 회의"** 로 두세요.)
4. 옛 폴더는 새 버전이 정상 동작하는지 확인한 뒤 지우세요.

> ⚠️ `MeetingMinutesData\config.json` 에는 API 키·메일 비밀번호가 평문으로 들어 있습니다.
> 이 폴더를 그대로 남에게 전달하지 마세요.

### 한국어 회의 전사에 섞이던 외국어·반복 제거 (가장 큰 수정)
무음/잡음 구간을 음성인식에 보내면 모델이 없는 말을 만들어냅니다. 그래서 한국어
회의인데 러시아어 조각(`Na velolodu`, `где-нибудь`)이 섞이고, 직전 문장이 문맥으로
다시 들어가면서 같은 문장이 수십 번 반복됐습니다.

- 발화가 없는 구간은 아예 전사하지 않습니다
- 직전 전사 문장을 모델에 되먹이지 않습니다(주제·참석자 힌트만 전달)
- 언어를 세션 내내 고정합니다(기본 **한국어**. `auto`는 조각마다 언어가 바뀌어 비권장)
- 남은 되풀이는 한 번으로 축약하고, 회의 언어에 없는 문자는 `[불명]`로 표시만 합니다
  (내용을 지우지 않습니다). 회의록 생성 AI는 `[불명]` 구간을 무시합니다
- 실측: 문제가 된 회의 앞 5분 71줄 → 45줄로 정리(중복 26줄 제거, 환각 3줄 표시)

  일치 유형·발화 내용까지 볼 수 있습니다
- 회의록: 맨 아래에 **"🔗 관련 노트"** 섹션이 자동으로 붙습니다(근거 링크 포함)
- 회의 상세: '참조된 관련 노트' 카드 + "최근 회의에서 자주 참조된 노트" 집계
- 노트 폴더나 검색 인덱스가 없으면 화면에 **비활성 사유**가 표시됩니다
  (설정 → 노트 폴더 지정 후 재인덱싱 필요)
- 웹 검색은 보완재입니다 — 내부 노트에서 찾은 구간에서는 웹을 호출하지 않습니다
  (기본값. 온라인 검색을 켠 경우에만 동작하며 웹 UI 녹음 전용)

### 녹음 화면이 계속 길어지던 문제
전사가 쌓일수록 페이지 전체가 늘어나 정지 버튼이 화면 밖으로 밀렸습니다.

- 전사 영역 높이를 화면 비율로 제한하고 그 안에서만 스크롤합니다
- 위로 올려 읽는 중엔 자동 스크롤이 멈추고 **"최신 전사로 (새 N줄)"** 버튼이 뜹니다
- 긴 회의는 화면에 최근 250줄만 표시(전체는 종료 후 전사 문서에서 확인)
- 회의록 상세 화면의 문서/스크립트 영역도 화면 높이에 맞춰 스크롤

### 음성 인식이 실패해도 회의 기록이 남게 (신규)
OpenAI 장애·키 문제·사내망 차단으로 음성 인식이 실패하면 지금까지는 회의 기록이
아예 남지 않았습니다. 이제 실패한 구간만 다른 경로로 자동 전환합니다.

- 순서: **OpenAI 기본 모델 → OpenAI 대체 모델 → Groq(다른 회사) → 이 PC(로컬)**
- **Groq 키**(선택·무료 발급, https://console.groq.com/keys)를 [설정]에 넣어두면
  OpenAI가 통째로 실패할 때 자동으로 넘어갑니다. 녹음 중이면 화면에 한 번 알립니다
  (화자분리는 없고, 요금은 OpenAI보다 저렴합니다)
- **인터넷이 아예 안 될 때**를 위한 로컬 백업도 포함됐습니다. 쓰려면 회의 **전에**
  [설정] → 고급 설정 → 오디오 전처리 → **[로컬 백업 모델 준비]** 를 한 번 누르세요
  (수십~수백 MB 다운로드, 1~3분). 회의 처리 도중에는 다운로드하지 않습니다 —
  최악의 순간에 몇 분을 멈추게 하는 대신, 준비가 안 됐으면 그 사실을 바로 알립니다
- 로컬 백업은 **녹음이 끝난 뒤 기록을 만들 때만** 쓰입니다(실시간 화면 표시는 Groq까지).
  컴퓨터 성능에 따라 녹음 길이의 1~3배 시간이 걸리고 정확도는 OpenAI보다 낮습니다

## 새 설정 (설정 → 실시간 녹취, 기본값 그대로 두면 됩니다)

| 설정 | 기본 | 설명 |
|---|---|---|
| 기본 언어 | `ko` | 회의 언어. `auto`는 비권장 |
| 무음 구간 전사 건너뛰기 | 켜짐 | 소리 없는 구간을 음성인식에 보내지 않음 |
| 전사 문맥 전달 방식 | `static` | 주제·참석자만 전달(반복 루프 차단) |
| 환각·반복 자동 정화 | 켜짐 | 되풀이 축약 + `[불명]` 표시 |
| 실시간 관련 노트 검색 (기능 토글) | 켜짐 | 녹음 중 내부 노트 표시 · 회의록에 근거 병합 |
| 웹검색은 내부 미발견 시만 | 켜짐 | 내부 노트를 찾은 구간은 웹 호출 생략(비용 절약) |

STT 폴백 관련 설정(설정 → API 키 / 모델 / 오디오 전처리):

| 설정 | 기본 | 설명 |
|---|---|---|
| Groq API 키 | 비어 있음 | 넣으면 OpenAI STT 실패 시 자동 폴백(선택) |
| STT 1차 폴백 모델(OpenAI) | `gpt-4o-transcribe` | 같은 OpenAI 내 재시도 모델 |
| STT 2차 폴백 모델(Groq) | `whisper-large-v3-turbo` | 빠름·저렴($0.04/시간) |
| STT 최종 백업 모델(로컬) | `base` | 클수록 정확하나 느림(CPU) |
| 로컬 STT 최종 백업 | 꺼짐 | 켜기 전에 [로컬 백업 모델 준비] 필요 |

목소리가 작아 전사가 잘게 끊기면 **무음 판정 임계값(RMS)** 을 100~200으로 낮추세요.
시끄러운 회의실이면 500~800으로 올립니다.

## 알려진 제약

- 실시간 화면에는 화자(누가 말했는지)가 표시되지 않습니다 — 필요하면 설정에서
  `realtime.diarize_postprocess` 를 켜세요(종료 후 재전사, 비용·시간 추가)
- **원거리 마이크는 인식 품질의 근본 한계입니다.** 노트북을 말하는 사람 쪽·회의실
  중앙에 두세요. 이번 수정은 "없는 말을 만들어내는 것"을 막지만, 애초에 안 들린
  말을 복원하지는 못합니다
- 전사 화면에 `[불명]` 이 보이면 그 구간은 음성인식이 잘못 만들어낸 것입니다
  (회의록에는 반영되지 않습니다)
- 로컬 백업(faster-whisper) **모델 가중치는 zip에 들어 있지 않습니다** — 라이브러리만
  포함이고, 가중치는 [설정]의 [로컬 백업 모델 준비]로 한 번 내려받아야 합니다
  (사내망에서 huggingface.co 가 막혀 있으면 이 준비가 실패할 수 있습니다)
- 원격 MCP(`/mcp`)는 포터블 배포본에 포함되지 않습니다(pywin32 재배치 문제).
  필요하면 별도로 올리는 **exe 릴리즈**를 쓰세요 — 단, exe 는 백신 스캔 때문에
  **첫 실행이 1~2분** 걸립니다(측정값 85초). 포터블은 약 10초입니다
