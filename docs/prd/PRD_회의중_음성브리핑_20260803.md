## 0. 요청과 그 해석

> "중간에 의견 정리해서 잘못된 거나 내용을 음성으로 말하는 서비스를 붙이는 건 어때?"

세 가지 서로 다른 기능이 한 문장에 들어 있다. **묶어서 판단하면 안 된다** — 난이도·위험·가치가 전부 다르다.

| 트랙 | 내용 | 지금 코드 | 위험 |
|---|---|---|---|
| **A** | 회의 **중간 요약**(지금까지의 논점·결정·액션 정리) | 없음 | 낮음(비용만) |
| **B** | 회의 중 **"잘못된 것" 지적**(사실 오류·앞말과의 모순) | 종료 후에만 존재 | **높음(사회적·정확성)** |
| **C** | 위 결과를 **음성으로 말하기**(TTS) | 없음 | 중간(되먹임·프라이버시) |

## 1. 지금 코드에 이미 있는 것 `[소스 검증]`

**이 절이 이 PRD의 핵심이다.** 요청의 상당 부분은 이미 구현돼 있고, 진짜 신규는 생각보다 작다.

| 기능 | 위치 | 상태 |
|---|---|---|
| 실시간 전사(2단계 보정) | `web/backend/api/realtime.py`, `common/realtime_ws_session.py` | 있음 |
| **회의 중 관련 노트 검색** | `wiki_core/realtime_search.py` `RealtimeVaultSearcher` | 있음, **기본 ON** |
| WS 이벤트 채널(브라우저로 밀어주기) | `realtime.py` — `segment`·`revise`·`related_notes`·`fact_check`·`status` 등 15종 | 있음 |
| **노트 대조(사실 검증)** | `meeting_pipeline/finalize.py` → `on_document("fact_check")` → WS `fact_check` | **종료 후 1회만** |
| 발화 단위 비블로킹 후처리 패턴 | `RealtimeVaultSearcher.offer_segment()` (핫패스 블로킹·raise 금지, 스레드풀, interval 게이트) | 있음 — **재사용 대상** |
| 비용 추정·한도·집계 단일 소스 | `common/pricing.py`, `spend_guard.blocked()`, `usage_log` | 있음 — **우회 금지** |
| 자동 실행 전역 일시정지 | `spend_guard.automation_paused()` | 있음 |

즉 **"중간에"가 새로운 부분이다.** 사실 검증은 존재하지만 회의가 끝난 뒤에만 돌고,
관련 노트는 회의 중에 뜨지만 그건 "정리"가 아니라 검색 결과 목록이다.

## 2. 목표 / 비목표

**목표**
- 긴 회의 중간에 참석자가 "지금까지 뭐가 정리됐지?"를 **화면을 안 보고도** 알 수 있게 한다.
- 그 요약이 **내부 노트와 어긋나면** 그 사실을 알린다(트랙 B, 조건부).
- 비용·자동 실행·프라이버시에서 기존 안전장치를 **우회하지 않는다**.

**비목표(명시적으로 하지 않는다)**
- 회의 진행자 대체(발언 순서 통제, 참석자 평가).
- 참석자 개인에 대한 판단("A 님 말이 틀렸다") — 화자 귀속 지적은 범위에서 제외한다.
- 실시간 화자분리 개선(별건, 이미 배치 후처리가 해법으로 결정됨).
- 외국어 실시간 통역 음성 출력.

## 3. 트랙 A — 회의 중간 요약 (구현 권고)

### FR-A1 트리거
- 기본 **비활성**. `realtime.midway_brief.enabled=false`.
- 켜면 두 조건 중 하나로 트리거: **경과 시간**(`interval_min`, 기본 10분) 또는 **사용자 버튼**
  (녹음 화면 [지금 정리]).
- 침묵 중에는 돌지 않는다 — 마지막 트리거 이후 **새 세그먼트가 N자 이상**(`min_new_chars`,
  기본 600) 쌓였을 때만. 근거: `RealtimeVaultSearcher` 가 이미 같은 이유로 interval +
  내용 게이트를 쓴다. `[소스 검증]`

### FR-A2 입력과 출력
- 입력: 마지막 트리거 이후의 세그먼트 + 이전 요약 1개(누적 압축). 전체 전사를 매번
  넣지 않는다 — 회의가 길어질수록 비용이 제곱으로 늘어난다. `[설계 판단]`
- 출력 JSON: `{ points: [...], decisions: [...], actions: [...], open_questions: [...] }`
- 화면: 녹음 화면에 접이식 카드로 누적 표시. WS 이벤트 `midway_brief` 신설
  (기존 15종과 같은 채널·같은 형식).

### FR-A3 비용
- **`pricing` 을 우회하지 않는다.** 요약 1회 비용을 `pricing.midway_brief_cost(llm, model)`
  로 추가하고, 예상 총액은 `estimate_session_cost()` 가 트리거 횟수를 곱해 포함한다.
  CLAUDE.md 의 "비용 단일 소스" 규칙 — 단가 표를 직접 `.get` 하면 안 된다. `[소스 검증]`
- 트리거마다 `spend_guard.blocked()` 를 지난다. 막히면 **조용히 건너뛰지 않고** 화면에
  "지출 한도로 중간 정리를 건너뜀"을 남긴다.
- 세션 비용 누적은 `db.add_session_cost()`(덮어쓰기인 `update_session_status` 아님).
- 개략치: 10분 간격·1시간 회의 = 6회. gpt-4o-mini 기준 회당 입력 ~2k·출력 ~400 토큰이면
  **세션당 $0.01 수준** `[미검증 — 실측 필요]`. 회의록 생성 1회($0.08, `MINUTES_COST_PER_SESSION`)
  보다 작다.

**수용 기준**
- 기본 설정에서 이 기능이 **한 번도 호출되지 않는다**(회귀 테스트로 고정).
- 켠 상태에서 침묵 20분 → 호출 0회.
- 한도 초과 시 호출 0회 + 화면에 사유 표시.
- 예상 비용 모달의 금액이 트리거 횟수를 반영한다(표시 금액과 한도 판정이 같은 함수).

## 4. 트랙 B — 회의 중 "잘못된 것" 지적 (보류 권고)

### 왜 보류인가

이 리포에는 **"조금이라도 위험하거나 비개발자가 쓰기 어려운 기능은 만들지 않고 검토·기록만"**
이라는 확립된 원칙이 있다. 트랙 B는 그 기준에 걸린다.

1. **틀린 지적의 비용이 비대칭이다.** 요약이 조금 어긋나면 사용자가 무시하면 되지만,
   "이 내용은 사실과 다릅니다"가 회의 중에 **틀리게** 나오면 발언자를 공개적으로 오정정한다.
   되돌릴 수 없는 사회적 비용이고, 그 오류율은 우리가 통제할 수 없다.
2. **근거가 약하다.** 회의 중에는 문맥이 잘려 있다(2단계 보정 전 조각 전사도 섞인다).
   종료 후 사실 검증이 전체 전사·노트 전량을 놓고 하는 판정과 신뢰도가 다르다.
3. **이미 종료 후 경로가 있다.** `finalize` 의 노트 대조가 같은 일을 더 좋은 조건에서 한다.
   회의 중으로 앞당겨 얻는 것은 "빠름"뿐이고 잃는 것은 정확도다.
4. 이 리포의 선례: **실측 없는 랭킹 휴리스틱을 금지**하는 원칙이 이미 있다. "무엇이 모순인가"
   판정은 그보다 더 주관적이다.

### 그래도 하려면 — 조건 (이 조건을 못 채우면 하지 않는다)

- 표현을 **지적이 아니라 대조**로 한정한다: "○○ 노트에는 △△로 적혀 있습니다"까지만.
  "틀렸다"는 판정 문구를 만들지 않는다.
- 화자를 붙이지 않는다(누가 말했는지 결부하지 않는다).
- **음성으로 내보내지 않는다**(화면 전용). 소리로 나가면 정정 불가능한 발화가 된다.
- 사전에 **오탐률 실측**이 있어야 한다: 실제 회의 5건에 대해 회의 중 대조 결과와 종료 후
  사실 검증 결과를 비교해 불일치율을 낸다. 기준 없이 켜지 않는다.

**결론**: v1 범위에서 제외. 트랙 A가 실사용에서 유용하다고 확인된 뒤 재검토한다.

## 5. 트랙 C — 음성 출력 (옵트인, 브라우저 TTS 우선)

### FR-C1 엔진 선택 — 브라우저 내장을 기본으로 한다

| 방식 | 비용 | 외부 전송 | CSP | 품질 |
|---|---|---|---|---|
| **Web Speech API** (`speechSynthesis`) | 0 | **없음**(OS 내장 음성) | `connect-src` 무관 — 네트워크 미사용 | 보통(Windows 한국어 음성 존재) |
| OpenAI TTS (`/v1/audio/speech`) | 유료 | 회의 요약문이 **외부로 나간다** | 백엔드 경유 필요 | 높음 |

**브라우저 TTS 를 기본·유일 구현으로 권고한다.** 근거:
- 배포본 CSP 는 방금 `connect-src 'self'` 로 좁혔다(`2090017`). OpenAI TTS 를 프런트에서
  직접 부르면 이 결정을 되돌리는 것이고, 백엔드 경유로 붙이면 새 프록시 엔드포인트 +
  과금 경로 + 관문이 생긴다. `[소스 검증]`
- 회의 요약문은 회의 내용 그 자체다. 전사·회의록은 이미 STT/LLM 벤더로 가지만, **음성 합성은
  가지 않아도 되는 추가 전송**이다. 안 보내도 되는 것을 보내지 않는다.
- 비용 0 이므로 `spend_guard` 를 새로 지날 필요가 없다.

품질이 부족하다는 피드백이 실제로 나오면 그때 OpenAI TTS 를 **옵트인 2차 옵션**으로 추가한다
(그때는 과금 경로이므로 `pricing`·`spend_guard`·관문을 모두 지나야 한다).

### FR-C2 되먹임 방지 — 이 기능의 진짜 난제 `[설계 판단]`

스피커로 낸 소리를 **같은 회의의 마이크가 다시 듣는다.** 그러면 STT 가 앱 자신의 음성을
전사하고, 그 전사가 다음 요약의 입력이 되어 자기 말을 요약하는 순환이 생긴다.
이 리포에는 유사 전례가 있다 — STT 프롬프트 되먹임을 제거한 수정(`project_stt_hallucination_ui`).

**대응(모두 필수)**
1. 재생 중에는 **STT 청크 전송을 일시 중단**한다(음소거가 아니라 업스트림 중단 — 마이크
   자체를 끄면 사용자가 그 사이 한 말이 사라진다는 오해가 생긴다. 중단 구간을 화면에 표시).
2. 기본 출력은 **헤드셋 사용 전제**로 안내하고, 스피커 사용 시 되먹임 가능성을 설정 화면에 명시.
3. 재생 문구를 **짧게**(기본 3문장 상한) — 중단 구간을 최소화한다.
4. 옵션: 재생 대신 **알림음 + 화면 표시**만(기본값). 음성 낭독은 명시적으로 켜야 한다.

### FR-C3 통제
- `realtime.voice_brief.enabled=false` 기본. `voice`(OS 음성 목록에서 선택), `rate`, `max_sentences`.
- 녹음 화면에 **즉시 정지** 버튼. 재생 중 다른 화면으로 이동하면 자동 정지.
- 회의 중 어느 시점에도 사용자가 껐으면 그 세션에서는 다시 켜지 않는다.

**수용 기준**
- 기본 설정에서 소리가 **나지 않는다**.
- 켠 상태에서 재생 중 STT 업스트림이 중단되고, 재생 종료 후 자동 재개된다.
- 재생 중 [정지]가 즉시 멈춘다(문장 경계 대기 없음).
- `speechSynthesis` 미지원·한국어 음성 없음 환경에서 **조용히 실패하지 않고** 사유를 표시한다
  (이 리포의 반복 규칙: 조용히 꺼지면 "기능이 없는 것처럼" 보인다 — `realtime_search.py` 주석).

## 6. 아키텍처 (트랙 A + C)

```
STT 세그먼트 확정 (realtime.py 핫패스)
   └─ MidwayBriefer.offer_segment(text)        ← RealtimeVaultSearcher 와 같은 계약
        · 논블로킹, raise 금지, 스레드풀
        · 게이트: enabled → interval → min_new_chars → spend_guard.blocked()
        · LLM 1회 → JSON
        └─ WS {"type": "midway_brief", ...}
              └─ 프런트: 카드 표시 + (옵트인 시) speechSynthesis 낭독
                    · 낭독 시작 → STT 업스트림 pause
                    · 낭독 종료/정지 → resume
```

**신규 파일**: `meeting_minutes_app/wiki_core/midway_brief.py`(또는 `meeting_pipeline/`),
프런트 `web/frontend/src/lib/tts.ts`.
**수정**: `realtime.py`(세그먼트 훅·WS 이벤트), `config_schema.py`(설정 2그룹),
`pricing.py`(요약 단가), `Recorder.tsx`(카드·정지 버튼), `Settings.tsx`(옵션).

**재사용해야 하는 것**(새로 만들면 갈라진다):
- 게이트·스레드 패턴: `RealtimeVaultSearcher`
- 비용: `pricing.*` + `spend_guard.blocked()` + `db.add_session_cost()`
- 설정 노출: `config_schema.SCHEMA`(tier=advanced)
- LLM 호출: `common/llm_client`(SSL·키·reload 훅이 이미 붙어 있다)

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| 되먹임으로 자기 음성을 전사 | FR-C2(재생 중 업스트림 중단) — **미검증, 실기 확인 필수** |
| 회의 흐름 방해(소리가 끼어든다) | 기본 비활성 + 알림음만 모드를 기본으로 + 즉시 정지 |
| 비용이 조용히 늘어남 | `pricing`·`spend_guard` 경유 강제 + 예상 비용 모달에 트리거 횟수 반영 |
| 요약이 부정확해 오해를 만듦 | "정리(초안)" 라벨 고정, 회의록으로 승격하지 않음, 원문 세그먼트 링크 제공 |
| OS 한국어 음성 부재 | 사유 표시 + 화면 표시로 폴백(조용히 꺼지지 않는다) |
| 사내 정책(회의 중 자동 개입) | 트랙 B 보류로 회피. 트랙 A·C 는 참석자에게 들리는 것이 **요약**뿐 |

## 부록 A — 이 PRD 를 쓰면서 정정한 내 오판

정직성을 위해 남긴다.

1. **"실시간 사실검증이 이미 있다"고 볼 수 있었다.** WS 이벤트 목록에 `fact_check` 가 있어
   그렇게 보였지만, 실제로는 `finalize`(종료 후) 에서만 발생한다(`realtime.py:1767`).
   회의 중 경로는 없다. 이벤트 이름만 보고 판단하면 틀린다.
2. **"TTS 는 OpenAI 로 붙이면 된다"가 첫 반응이었다.** 그런데 방금 배포본 CSP 를
   `connect-src 'self'` 로 좁힌 상태이고(`2090017`), 회의 요약문을 굳이 외부로 보낼 이유도
   없다. 브라우저 내장 TTS 가 비용 0·외부 전송 0 이라 더 낫다 — 기본 선택을 바꿨다.
3. **되먹임을 처음에 놓쳤다.** 스피커 출력이 같은 회의의 마이크로 되돌아오는 문제는 이 기능의
   가장 큰 난제인데, 요청 문장만 읽으면 드러나지 않는다.
